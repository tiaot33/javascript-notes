# 01 递归和堆栈

> 原文：`zh.javascript.info/1-js/06-advanced-functions/01-recursion/article.md`
> 递归思想与 Java 完全一致，**重点是理解 JS 的"执行上下文堆栈"**，它是理解闭包的前置知识。

## 知识点

### 1. 递归的两个要素
- **递归步骤**：把任务拆成"简单行为 + 同类型但更小的任务"。
- **递归基础（base case）**：不需要再拆分的终止条件。

```js
function pow(x, n) {
  return (n == 1) ? x : (x * pow(x, n - 1)); // 递归解通常比循环更短
}
```

- **递归深度**：最大嵌套调用次数（含首次）。JS 引擎可靠支持约 10000 层，100000 层以上大多超限。
- 尾调用优化（TCO）规范存在但引擎基本没有实现，**不要指望它**。

### 2. 执行上下文堆栈（重点概念）
- 每次函数调用对应一个 **执行上下文**（内部数据结构）：保存当前执行位置、局部变量、`this` 等。
- 嵌套调用时：当前上下文被 **压入执行上下文堆栈** 暂停 → 执行子调用 → 子调用结束后 **弹栈恢复**。
- 递归深度 = 堆栈中上下文的最大数量；**每个上下文都占内存**，深度为 n 的递归要存 n 个上下文。

```
pow(2,3) 调用时的堆栈（栈顶在上）：
Context: { x:2, n:1, at line 1 }   pow(2,1)  ← 当前运行
Context: { x:2, n:2, at line 5 }   pow(2,2)
Context: { x:2, n:3, at line 5 }   pow(2,3)
```

- **任何递归都可以改写为循环**，循环只用一个上下文、内存固定且通常更高效；但递归代码往往更短、更易理解和维护，不是每个地方都值得优化。

### 3. 递归遍历（实战高频）
适合"树状/嵌套层级未知"的结构：数组是叶子、对象继续拆分子调用。

```js
function sumSalaries(department) {
  if (Array.isArray(department)) {          // 情况1：数组 → 基础递归
    return department.reduce((prev, cur) => prev + cur.salary, 0);
  } else {                                   // 情况2：对象 → 递归求和子部门
    let sum = 0;
    for (let subdep of Object.values(department)) {
      sum += sumSalaries(subdep);
    }
    return sum;
  }
}
```

### 4. 递归结构
- 用自身定义自身的数据结构（HTML 树、部门树）。
- **链表**：`{ value, next -> 链表 | null }`。
  - 优点：任意位置插入/删除只需改 `next` 引用，无需大规模重排（数组的 `unshift/shift` 要重新编号所有元素）。
  - 缺点：不能按下标直接访问，取第 N 个要从头走 N 步。
  - 增强方向：加 `prev` 成双向链表、加 `tail` 引用尾部。

```js
// 头部插入：list = { value: "new", next: list };
// 中间删除：list.next = list.next.next;
```

## 与 Java 对比
| Java | JS | 说明 |
|---|---|---|
| 每次方法调用压入 JVM 栈帧 | 每次调用创建执行上下文压栈 | 机制一致；JS 栈深约 1 万层，比 JVM 默认栈（512K~1M）更容易溢出 |
| `StackOverflowError` | `RangeError: Maximum call stack size exceeded` | 递归过深的报错 |
| 无尾调用优化（JVM 层） | 规范有 TCO 但引擎未实现 | 两边都不能依赖尾递归 |
| `java.util.LinkedList` | 手写 `{value, next}` 对象链 | JS 没有内置链表，需要自己用对象实现 |
| 遍历树结构用递归 | 同样用递归，配合 `Object.values()` | 思路一致，JS 处理嵌套 JSON 比 Java 处理 Map/List 嵌套简洁得多 |

## 一句话总结
递归 = 递归步骤 + 基础条件；每次调用创建一个执行上下文压栈（深度即栈中上下文数，约 1 万层上限），任何递归都能改写为循环（循环更省内存），递归的真正主场是遍历"层级未知"的递归结构（树、链表 `{value, next}`），配合 `Array.isArray` 分叶子/分支两种情况处理即可。
