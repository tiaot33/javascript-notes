# 12 深入理解箭头函数

> 原文：`zh.javascript.info/1-js/06-advanced-functions/12-arrow-functions/article.md`
> **ES6 核心**。箭头函数不只是语法糖，它专治"把函数传出去之后 `this` 变了"的问题。

## 知识点

### 1. 箭头函数没有 `this`（核心特性）
访问 `this` 时，箭头函数从**外部词法环境**获取（和普通变量查找同一套规则）：

```js
let group = {
  title: "Our Group",
  students: ["John", "Pete", "Alice"],
  showList() {
    this.students.forEach(
      student => alert(this.title + ': ' + student) // this=group ✓
    );
  }
};
```
用普通函数则报错：`forEach` 回调的 `this` 是 `undefined`（严格模式默认 `this`），访问 `undefined.title` 抛错。

### 2. 不能 `new`
没有 `this` → 不能用作构造器，不能用 `new` 调用。

### 3. 箭头函数 vs `.bind(this)`
- `.bind(this)`：创建函数的**绑定版本**，this 被固化。
- 箭头函数：没有绑定任何东西，它干脆没有 `this`，`this` 的查找走词法作用域（和普通变量一样）。

### 4. 没有 `arguments`
- 箭头函数没有自己的 `arguments`，访问到的是外层普通函数的。
- 装饰器转发福音——希望转发 `this` 和 `arguments` 时用箭头函数最简洁：

```js
function defer(f, ms) {
  return function() {
    setTimeout(() => f.apply(this, arguments), ms);
  };
}

// 不用箭头函数的等价写法（要多存两个变量）：
function defer(f, ms) {
  return function(...args) {
    let ctx = this;
    setTimeout(function() {
      return f.apply(ctx, args);
    }, ms);
  };
}
```

### 5. 适用场景
箭头函数就是为"写在别处执行的短回调"而生：没有 `this`、没有 `arguments`、不能 `new`、没有 `super`（继承一章讲），封装外部上下文是它的舒适区。

## 与 Java 对比
| Java | JS | 说明 |
|---|---|---|
| lambda：`this` 指向**外部类实例** | 箭头函数：`this` 取自外部词法环境 | **行为完全一致**，Java lambda 相当于 JS 箭头函数 |
| 匿名内部类：`this` 指向**自身** | 普通函数：`this` 取调用现场 | 对应关系，Java 的匿名类反而是"普通函数"行为 |
| `() -> {...}` | `() => {...}` | 语法也几乎一样，容易上手 |

## 一句话总结
箭头函数 `=>` 没有 `this`（沿词法作用域向外找，和普通变量同规则）、没有 `arguments`、不能 `new`、没有 `super`——这正适合"被传到别处执行的短回调"：在对象方法里 `forEach(student => ...)` 的 `this` 能正确指向外部对象，普通函数回调则会拿到 `undefined` 的 `this`；做装饰器转发时不需手工保存 `ctx` 和 `args`，一行 `f.apply(this, arguments)` 透明转发，这就是它胜过 `.bind(this)` 的原因。
