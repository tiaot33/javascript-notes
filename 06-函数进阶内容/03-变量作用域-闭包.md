# 03 变量作用域，闭包

> 原文：`zh.javascript.info/1-js/06-advanced-functions/03-closure/article.md`
> **本章最重要的一篇，JS 的灵魂概念**，面试必问。理解"词法环境"是理解一切作用域/闭包问题的钥匙。

## 知识点

### 1. 代码块作用域
- `let/const` 在 `{...}` 块内声明的变量只在块内可见（`if`、`for`、`while` 的块都算）。
- 同一作用域用 `let` 重复声明同名变量 → **报错**。
- `for (let i ...)` 中声明的 `i` 虽然在 `{}` 外面写，但被视为块的一部分，循环外不可见。

### 2. 嵌套函数
- 函数内部可以再声明函数，内层函数可访问外层变量。
- 外层函数可以**把嵌套函数返回出去**，之后在任何地方调用，它仍然能访问创建时的外部变量：

```js
function makeCounter() {
  let count = 0;
  return function() {
    return count++;
  };
}
let counter = makeCounter();
counter(); // 0
counter(); // 1  —— makeCounter 早已执行完，count 却还在增长
```

### 3. 词法环境（Lexical Environment）——核心机制
每个运行的函数、代码块、整个脚本都关联一个隐藏的**词法环境**对象，由两部分组成：
1. **环境记录（Environment Record）**：存所有局部变量（和 `this` 值）的对象。
2. **外部词法环境引用（outer）**：指向外层环境。

- **变量 = 环境记录对象的属性**，读/写变量就是读/写该对象的属性。
- 脚本开始时，词法环境**预先填充所有声明**：
  - `let` 变量初始处于 **Uninitialized** 状态（暂时性死区），声明语句执行前访问会报错；执行到 `let` 语句后变为 `undefined`。
  - **函数声明则一步到位**：词法环境创建时就初始化完毕，所以声明之前就能调用（提升）。
- 访问变量的搜索顺序：**内部环境 → 外部环境 → … → 全局环境**，都找不到时严格模式报错（非严格模式下给未声明变量赋值会创建全局变量）。

### 4. `[[Environment]]` 与闭包的形成
- **所有函数在"诞生"时通过隐藏属性 `[[Environment]]` 记住创建它的词法环境**，此后无论在哪调用都不变。
- 函数调用时创建的新词法环境，其 outer 引用就取自 `[[Environment]]`。
- **在变量所在的词法环境中修改变量**：`counter()` 修改的是 `makeCounter` 那次调用的环境记录里的 `count`，所以能持续累加。
- 每次调用 `makeCounter()` 都创建**独立的新词法环境**，多个 counter 互不影响。

### 5. 闭包的定义（面试标准答案）
> **闭包 = 能记住并访问其外部变量的函数。**

- 在 JS 中**所有函数天生都是闭包**（唯一例外是 `new Function`，见第 07 篇），因为每个函数都有 `[[Environment]]`。
- 面试回答要点：定义 + 为什么 JS 函数全是闭包 + `[[Environment]]` 和词法环境的技术细节。

### 6. 垃圾回收
- 函数调用结束后，其词法环境通常随之销毁。
- 但如果返回的嵌套函数仍可达（被引用着），词法环境就**因 `[[Environment]]` 引用而存活**：

```js
let arr = [f(), f(), f()]; // 3 个函数各自持有 3 个词法环境
g = null;                  // 嵌套函数不可达 → 词法环境（含其中的 value）被回收
```

### 7. V8 优化副作用（调试时的坑）
- 理论上嵌套函数可达时外部变量全保留；实际 V8 会分析并**删掉未被使用的外部变量**。
- 副作用：**调试时这些变量在 Console 里访问不到**（`No such variable!`），甚至同名的更外层变量会"冒出来"，这不是 bug 而是 V8 特性。

## 与 Java 对比
| Java | JS | 说明 |
|---|---|---|
| 块级作用域 `{ int x; }` | `let` 块级作用域 | 一致；JS 的 `var` 没有块级作用域（见下篇） |
| lambda/匿名类只能捕获 **effectively final** 的局部变量 | 闭包捕获**变量本身**，可读可写 | 重大差异！JS 闭包是活的引用，`count++` 合法；Java 里必须包成 `AtomicInteger` 或数组 |
| 匿名内部类持有外部变量 | 函数通过 `[[Environment]]` 持有词法环境 | 机制相似，JS 的绑定是"按变量"而非"按值快照" |
| `private` 字段隐藏状态 | 闭包变量外部完全无法访问 | `makeCounter` 的 `count` 比 Java private 更彻底（连反射都摸不到），常用来实现真正的私有状态 |
| lambda 是 SAM 接口实例 | 函数是一等公民，可直接返回/传递 | JS 没有接口约束，函数自由流动 |

## 一句话总结
JS 中每个函数/代码块/脚本都有词法环境（环境记录 + outer 引用），函数创建时通过 `[[Environment]]` 永久记住出生地，变量查找沿 outer 链向上直到全局——所以**所有 JS 函数天生是闭包**，返回的嵌套函数会让其外部词法环境一直存活（这就是私有状态的实现方式）；与 Java lambda 的最大区别是 JS 闭包捕获的是**可写的变量本身**，而非 effectively final 的快照。
