# 10 函数绑定

> 原文：`zh.javascript.info/1-js/06-advanced-functions/10-bind/article.md`
> 解决 JS 的经典痛点：**对象方法当回调传出去时 `this` 丢失**。

## 知识点

### 1. 丢失 `this` 的问题
方法一旦与对象分离（传给 `setTimeout`、赋给变量、作为回调），`this` 就丢了：

```js
let user = {
  firstName: "John",
  sayHi() { alert(`Hello, ${this.firstName}!`); }
};
setTimeout(user.sayHi, 1000); // "Hello, undefined!" ❌

// 等价于：
let f = user.sayHi;
setTimeout(f, 1000); // 脱离了对象
```
浏览器里 `setTimeout` 会把 `this` 设为 `window`（一般回调场景则是 `undefined`）。

### 2. 解决方案 1：包装器（有漏洞）
```js
setTimeout(function() { user.sayHi(); }, 1000); // ✓ 闭包捕获 user
setTimeout(() => user.sayHi(), 1000);           // 更简短的写法
```
漏洞：触发前 `user` 被重新赋值，调用的就是新对象（闭包捕获的是变量名，不是对象）：

```js
setTimeout(() => user.sayHi(), 1000);
user = { sayHi() { alert("Another user!"); } }; // 1 秒内变了 → 调错对象
```

### 3. 解决方案 2：`bind`（推荐）
```js
let boundFunc = func.bind(context);
```
- 返回一个"绑定变体"：可像普通函数调用，`this` 固定为 `context`，参数原样传递。

```js
let sayHi = user.sayHi.bind(user);
sayHi();                  // Hello, John! 脱离对象也能调
setTimeout(sayHi, 1000);  // 传给调度器也没问题
user = { ... };           // 之后重赋值 user 也不影响，bind 绑的是旧对象引用
```

- 批量绑定一个对象的所有方法：

```js
for (let key in user) {
  if (typeof user[key] == 'function') {
    user[key] = user[key].bind(user);
  }
}
// lodash 提供 _.bindAll(object, methodNames)
```

### 4. 部分应用函数（partial function）
`bind` 的完整语法还能**预绑定参数**：

```js
let bound = func.bind(context, arg1, arg2, ...);

function mul(a, b) { return a * b; }
let double = mul.bind(null, 2);
double(3); // = mul(2, 3) = 6
let triple = mul.bind(null, 3);
```

- 不用 `this` 时传 `null` 占位。
- 用途：把通用函数固化成语义化的变体（`double`、`triple`、`sendTo`），少重复参数。

### 5. 只要绑定参数不要 this：手写 `partial`
原生 `bind` 必须给上下文，想只绑参数可以自己实现：

```js
function partial(func, ...argsBound) {
  return function(...args) {
    return func.call(this, ...argsBound, ...args); // this 透传，参数拼在前面
  };
}

user.sayNow = partial(user.say, new Date().getHours() + ':' + new Date().getMinutes());
user.sayNow("Hello"); // [10:00] John: Hello!
// lodash: _.partial
```

## 与 Java 对比
| Java | JS | 说明 |
|---|---|---|
| 方法引用 `user::sayHi` 自带 receiver，永不丢 | `user.sayHi` 传递即丢失 `this` | JS 最大的坑之一；Java 编译器帮你捕获 `this` |
| lambda 包装：`() -> user.sayHi()` | 包装器 `() => user.sayHi()` | 对应"解决方案 1" |
| 无对应（方法引用就解决了） | `func.bind(context)` | bind 是 JS 的显式补救工具 |
| 无原生柯里化（需第三方库如 Vavr） | `func.bind(null, fixedArg)` 部分应用 | JS 一行实现柯里化/函数工厂 |
| `this` 永远隐式传递 | `this` 是显式可操控的值 | JS 的灵活性代价：要自己管 `this` |

## 一句话总结
对象方法一旦脱离对象传递（入 `setTimeout`/回调），`this` 就丢；用 `func.bind(context)` 返回绑定变体，脱离对象调用也安全，`bind` 还能预绑定参数做**部分应用函数**（`mul.bind(null, 2)` ≈ 柯里化）；包装器写法 `() => user.sayHi()` 也能救急，但 `bind` 不受外层变量重赋值影响；要批量绑定全对象方法可用循环或 lodash `_.bindAll`，只绑参数不绑 this 则手写 `partial`（或 lodash `_.partial`）。
