## 一、属性标志和属性描述符

> 原文：`zh.javascript.info/1-js/07-object-properties/01-property-descriptors/article.md`
> **ES5 就有的东西，但日常代码里很少显式出现**。对象属性不只是"键值对"，每个属性还带三个标志位；理解它们是读懂 `Object.freeze`、类的 getter/setter、以及各种库源码的基础。

### 知识点

#### 1. 属性的三个标志（flags / attributes）
除了 `value`，每个数据属性还有：

| 标志 | 为 `true` 时 | 为 `false` 时 |
|---|---|---|
| `writable` | 值可修改 | 只读 |
| `enumerable` | 会出现在 `for..in` / `Object.keys` 中 | 被循环和 `Object.keys` 忽略 |
| `configurable` | 可删除、可修改标志 | 不能 `delete`，不能再改标志 |

用"常规方式"（字面量、赋值）创建的属性，三个标志**全为 `true`**。

#### 2. 读取描述符：`Object.getOwnPropertyDescriptor(obj, prop)`
返回"属性描述符"对象，包含 `value` 和所有标志：

```js
let user = { name: "John" };
Object.getOwnPropertyDescriptor(user, 'name');
// { value: "John", writable: true, enumerable: true, configurable: true }
```

#### 3. 修改/定义：`Object.defineProperty(obj, prop, descriptor)`
- 属性**已存在**：只更新给出的标志，没给的保持不变。
- 属性**不存在**：用给定 value 和标志新建；**没写的标志一律默认为 `false`**。

```js
let user = {};
Object.defineProperty(user, "name", { value: "John" });
// → writable: false, enumerable: false, configurable: false（全 false！）
```
> 坑：用 `defineProperty` 新建属性时，想要正常行为必须显式写 `enumerable: true, configurable: true, writable: true`。

#### 4. `writable: false` —— 只读
```js
Object.defineProperty(user, "name", { writable: false });
user.name = "Pete"; // 严格模式下 TypeError；非严格模式静默失败
```
- **只有严格模式才报错**，非严格模式下违反标志的操作被默默忽略（这也是要用 `"use strict"` 的一个理由）。
- 只读不等于安全：别人仍可用自己的 `defineProperty` 覆盖回来（除非同时 `configurable: false`）。

#### 5. `enumerable: false` —— 不可枚举
- 内建方法如 `toString` 都是不可枚举的，所以 `for..in` 看不到它们。
- 自己给对象加的 `toString` 默认可枚举，会被 `for..in` 列出；设成 `enumerable: false` 即可隐藏。
- 不可枚举属性同样被 `Object.keys` 排除，但仍能直接访问（`user.toString()` 照常工作）。

#### 6. `configurable: false` —— 不可配置（单行道）
- 不能 `delete`，不能再修改任何标志，**也不能改回 `configurable: true`**。
- **但不影响改值**：`configurable: false` + `writable: true` 时，`user.name = "Pete"` 依然可以。
- 要做成 `Math.PI` 那种"真常量"，需同时 `writable: false, configurable: false`。
- 唯一例外：不可配置属性允许把 `writable` 从 `true` 改成 `false`（只能加锁，不能解锁）。

```js
Object.getOwnPropertyDescriptor(Math, 'PI');
// { value: 3.14159..., writable: false, enumerable: false, configurable: false }
Math.PI = 3;                                          // 无效
Object.defineProperty(Math, "PI", { writable: true }); // Error
```

#### 7. 批量操作
- `Object.defineProperties(obj, { p1: desc1, p2: desc2 })` —— 一次定义多个属性。
- `Object.getOwnPropertyDescriptors(obj)` —— 一次拿到所有属性的描述符，**包含 symbol 键和不可枚举属性**。

两者配合可做"保留标志的克隆"：
```js
let clone = Object.defineProperties({}, Object.getOwnPropertyDescriptors(obj));
```
对比 `for (key in obj) clone[key] = obj[key]`：后者丢失标志，且跳过 symbol 和不可枚举属性。

#### 8. 整个对象级别的封锁
| 方法 | 效果 | 对现有属性的影响 |
|---|---|---|
| `Object.preventExtensions(obj)` | 禁止新增属性 | 无 |
| `Object.seal(obj)` | 禁止新增/删除 | 全部 `configurable: false` |
| `Object.freeze(obj)` | 禁止新增/删除/修改 | 全部 `configurable: false, writable: false` |

对应检测：`Object.isExtensible` / `Object.isSealed` / `Object.isFrozen`。
- 三者都是**浅层**的：`freeze` 后嵌套对象仍可改。
- 原文说实际中很少用；不过 `Object.freeze` 在配置常量、Redux 式不可变数据里还是比较常见。

### 与 Java 对比
| Java | JS | 说明 |
|---|---|---|
| `final` 字段 | `writable: false` | 都只锁引用/值本身，不锁对象内部 |
| 字段的可见性由 `private` 等修饰符控制 | 没有访问修饰符，只有"可枚举/可写/可配置" | JS 的标志不是访问控制，`enumerable: false` 的属性仍能直接读 |
| `Collections.unmodifiableMap` 等只读视图 | `Object.freeze(obj)` | 都是浅层不可变；Java 是包装视图，JS 是原地修改对象元数据 |
| 编译期检查，违规直接编译失败 | 运行时检查，且仅严格模式抛错 | 非严格模式静默失败很隐蔽，务必开 `"use strict"` 或用模块/class（自动严格） |
| 反射 `Field.setAccessible` 等 | `getOwnPropertyDescriptor` / `defineProperty` | 都是"元编程"入口，但 JS 的更轻量、更常用 |

## 二、属性的 getter 和 setter

> 原文：`zh.javascript.info/1-js/07-object-properties/02-property-accessors/article.md`
> **ES5 引入，ES6 class 中大量使用**。对 Java 开发者来说这是最"羡慕"的特性之一：不用写 `getXxx()/setXxx()`，外部代码按普通属性读写，内部却是函数。

### 知识点

#### 1. 两类属性
- **数据属性（data property）**：有 `value`，之前用的全是这种。
- **访问器属性（accessor property）**：本质是一对 getter/setter 函数，但从外部看就是普通属性。

#### 2. 对象字面量中的 `get` / `set`
```js
let user = {
  name: "John",
  surname: "Smith",

  get fullName() {
    return `${this.name} ${this.surname}`;
  },
  set fullName(value) {
    [this.name, this.surname] = value.split(" ");
  }
};

user.fullName;                  // 读取 → 触发 getter → "John Smith"
user.fullName = "Alice Cooper"; // 赋值 → 触发 setter
```
- 读 `obj.prop` 时调 getter，写 `obj.prop = v` 时调 setter；**不是**以 `user.fullName()` 方式调用。
- 只有 getter 没有 setter 时，赋值会报错（严格模式）——属性变成只读的"虚拟属性"。

#### 3. 访问器描述符
访问器属性的描述符**没有 `value` 和 `writable`**，取而代之的是：
- `get` —— 无参函数，读取时调用
- `set` —— 单参函数，赋值时调用
- `enumerable`、`configurable` —— 与数据属性相同

```js
Object.defineProperty(user, 'fullName', {
  get() { return `${this.name} ${this.surname}`; },
  set(value) { [this.name, this.surname] = value.split(" "); }
});
```
> 注意：一个属性**要么**是数据属性（`value`），**要么**是访问器（`get/set`），不能两者兼有。描述符里同时写 `get` 和 `value` 会抛 `Invalid property descriptor`。
> 同样，`defineProperty` 定义的访问器默认 `enumerable: false`，上例中 `for..in` 只会列出 `name, surname`。

#### 4. 用 getter/setter 包装"真实"属性（校验）
```js
let user = {
  get name() { return this._name; },
  set name(value) {
    if (value.length < 4) {
      alert("Name is too short, need at least 4 characters");
      return;
    }
    this._name = value;
  }
};
```
- 真实值放在 `_name`，对外暴露 `name`，在 setter 里做校验。
- 下划线前缀 `_xxx` 只是**约定**表示"内部属性，外部别碰"，语言层面并不阻止访问。真正的私有字段是 `#xxx`（class 章节会讲）。
- 坑：getter 里不能写 `return this.name`，会无限递归调用自己。

#### 5. 兼容性 / 平滑演进
访问器最大的价值：可以随时把一个已被外部使用的**数据属性**换成 getter/setter，调用方零改动。

```js
function User(name, birthday) {
  this.name = name;
  this.birthday = birthday;

  // 旧代码用 age，现在改存 birthday，用 getter 动态算出 age
  Object.defineProperty(this, "age", {
    get() {
      let todayYear = new Date().getFullYear();
      return todayYear - this.birthday.getFullYear();
    }
  });
}
```
这正是 JS 社区"不需要预防性地给每个字段都写 getter/setter"的理由：需要时再加，对外接口不变。

### 与 Java 对比
| Java | JS | 说明 |
|---|---|---|
| `getFullName()` / `setFullName(v)` 方法 | `get fullName()` / `set fullName(v)` 访问器 | JS 调用方写 `user.fullName`，看起来像字段。类似 Kotlin/C# 的 property |
| 一开始就把字段设 `private` 并生成 getter/setter，以防将来要改 | 先用普通属性，需要时再无痛换成访问器 | JS 里 JavaBean 式"预防性封装"没必要 |
| `private` 字段，编译器强制 | `_name` 只是命名约定；真私有用 `#name`（class） | 见后续 class 章节 |
| 在 setter 里做参数校验 | 同样在 `set` 里校验，失败可 `return`/抛错 | 思路一致 |
| Lombok `@Getter/@Setter` | 语言原生支持，无需工具 | |
