# 03 现代模式，"use strict"

> 原文：`zh.javascript.info/1-js/02-first-steps/03-strict-mode/article.md`

## 知识点

### 1. 背景
- JS 长期保持向后兼容，早期设计的错误被永久保留。
- 2009 年 ES5 引入新特性并修改了一些旧行为，为了兼容旧代码，这些修改**默认不生效**，需要用 `"use strict"` 显式开启。

### 2. 用法
- 写在脚本文件**最顶部**（只能有注释在它前面），整个文件以严格模式运行：

```js
"use strict";
// 代码以现代模式工作
```

- 也可以放在函数体开头，只对该函数启用。
- 不在顶部会被忽略，严格模式不会启用。
- **无法取消**：没有 `"no use strict"`，一旦进入就没有回头路。

### 3. 浏览器控制台
- 开发者控制台默认**不启用**严格模式。
- 启用方法：用 `Shift+Enter` 换行，把 `'use strict';` 写在第一行；或用 IIFE 包裹：

```js
(function() {
  'use strict';
  // ...你的代码...
})()
```

### 4. 是否应该使用？
- **class 和 module 会自动启用严格模式**，使用它们时无需再写 `"use strict"`。
- 现阶段建议在脚本顶部写上；以后代码都在 class / module 中时可省略。
- 教程所有示例默认采用严格模式。

### 5. 严格模式的典型影响（后续章节会陆续遇到）
- 未声明变量直接赋值会报错（非严格模式下会隐式创建全局变量，见第 4 篇）。
- 差异不多，且都是让语言行为更合理。

## 与 Java 对比
- Java 没有"模式切换"的概念；JS 的严格模式可以理解为"把语言早期的宽松行为改为像 Java 一样严格报错"。
- 现代 JS 工程（ES 模块、打包工具、框架）几乎都在严格模式下运行，实际开发中很少需要手写这一行。

## 一句话总结
`"use strict"` 放文件顶部开启现代模式，不可取消；class 和 module 自动启用；写现代 JS 时默认以严格模式思考。
