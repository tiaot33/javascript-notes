# 07 类型转换

> 原文：`zh.javascript.info/1-js/02-first-steps/07-type-conversions/article.md`

## 知识点

### 0. 概述
- 大多数情况下运算符和函数会**自动**把值转换为需要的类型（隐式转换）：`alert` 把任何值转成字符串显示；算术运算符把值转成数字。
- 也可以**显式**转换：`String(x)`、`Number(x)`、`Boolean(x)`。
- 本章只讨论原始类型，对象的转换后续 `object-toprimitive` 章节再讲。

### 1. 字符串转换
- 发生在需要字符串的场景，如 `alert(value)`。
- 显式：`String(value)`。

```js
let value = true;
alert(typeof value); // boolean

value = String(value); // 现在是字符串 "true"
alert(typeof value); // string
```

- 规则最直观：`false` → `"false"`，`null` → `"null"`，`undefined` → `"undefined"`。

### 2. 数字型转换
- 在算术函数和表达式中自动进行：

```js
alert( "6" / "2" ); // 3，字符串被自动转成数字后计算
```

- 显式：`Number(value)`。从表单等字符串源读取数据、期望得到数字时，通常需要显式转换。
- 字符串不是有效数字时结果为 `NaN`：

```js
let age = Number("an arbitrary string instead of a number");
alert(age); // NaN，转换失败
```

**数字型转换规则**：

| 值 | 变成 |
|---|---|
| `undefined` | `NaN` |
| `null` | `0` |
| `true` / `false` | `1` / `0` |
| `string` | 去掉首尾空白字符（空格、`\n`、`\t` 等）后"按原样读取"；剩余为空字符串 → `0`；读取出错 → `NaN` |

```js
alert( Number("   123   ") ); // 123
alert( Number("123z") );      // NaN（读到 "z" 出错）
alert( Number(true) );        // 1
alert( Number(false) );       // 0
```

- **注意 `null` 和 `undefined` 的差别**：`null` → `0`，`undefined` → `NaN`。

### 3. 布尔型转换
- 发生在逻辑运算中（`if`、`&&`、`||` 等），也可显式 `Boolean(value)`。
- 规则最简单：

| 值 | 变成 |
|---|---|
| `0`、`""`、`null`、`undefined`、`NaN` | `false`（假值 falsy） |
| 其他所有值 | `true`（真值 truthy） |

```js
alert( Boolean(1) );       // true
alert( Boolean(0) );       // false
alert( Boolean("hello") ); // true
alert( Boolean("") );      // false
```

- **坑：非空字符串永远是 `true`**，包括 `"0"` 和只有空格的 `" "`（PHP 等语言把 `"0"` 视为 false，JS 不是）：

```js
alert( Boolean("0") ); // true
alert( Boolean(" ") ); // true
```

### 4. 容易犯错的点（原文总结）
- `undefined` 数字转换是 `NaN`，不是 `0`。
- `"0"` 和 `"   "` 布尔转换是 `true`。

## 与 Java 对比
| Java | JS | 说明 |
|---|---|---|
| `String.valueOf(x)` / `"" + x` | `String(x)`，或隐式（`alert`、字符串拼接） | 效果类似，JS 隐式发生的场景更多 |
| `Integer.parseInt("123")`，非法输入抛 `NumberFormatException` | `Number("123")`，非法输入返回 `NaN`，**不抛异常** | 必须自己检查 `NaN`（后续会学 `isNaN`/`Number.isNaN`） |
| `parseInt(" 123 ")` 抛异常（不容忍空白） | `Number(" 123 ")` → `123` | JS 自动去首尾空白 |
| `Integer.parseInt("")` 抛异常 | `Number("")` → `0` | 空字符串变 0 是隐蔽的坑 |
| 布尔与数字/字符串**不能**互转（`if (1)` 编译错误） | 任何值都能转布尔，`if (1)`、`if ("abc")` 合法 | truthy/falsy 概念是 Java 没有的，必须记住 5 个假值 |
| `"6" / "2"` 编译错误 | `"6" / "2"` → `3` | 算术运算符对字符串自动转数字 |
| `null` 参与算术抛 NPE | `null` 变 `0`，`undefined` 变 `NaN` | 不报错，结果悄悄出错，调试时要注意 |

**实践建议**：
- 从 `prompt`/表单/URL 拿到的都是字符串，用数字前显式 `Number()` 转换，并检查是否为 `NaN`。
- 判断"空"时不要依赖隐式布尔转换处理 `0` 和 `""` —— 它们是合法值却是假值；明确用 `=== null`、`=== undefined` 或 `=== ""` 判断。
- 记住假值只有这 5 个（对象章节后再加上：所有对象包括空数组 `[]`、空对象 `{}` 都是真值）：`0`、`""`、`null`、`undefined`、`NaN`（以及 `-0`、`0n`）。

## 一句话总结
三种转换：转字符串（`String()`，最直观）、转数字（`Number()`，失败得 `NaN`，`null`→0、`undefined`→NaN、空串→0）、转布尔（`Boolean()`，只有 `0`/`""`/`null`/`undefined`/`NaN` 是假值，`"0"` 是真值）。
