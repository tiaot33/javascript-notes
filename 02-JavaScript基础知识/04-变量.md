# 04 变量

> 原文：`zh.javascript.info/1-js/02-first-steps/04-variables/article.md`

## 知识点

### 1. 声明变量：`let`
- 变量是数据的"命名存储"。用 `let` 声明，用 `=` 赋值，可合并成一行：

```js
let message;
message = 'Hello';

let user = 'John';   // 声明并赋值
```

- 一行可以声明多个（`let a = 1, b = 2;`），但**推荐一行一个**，可读性更好。
- **重复声明同一变量会报错**：`SyntaxError: 'message' has already been declared`。声明一次后，再使用时不带 `let`。

### 2. `var`（老写法）
- 老代码中用 `var` 声明变量，与 `let` 大体相同但有微妙差别（作用域等），现代代码不再使用，后续 `var` 章节详述。

### 3. 变量是一个"盒子"
- 可以反复改变盒子里的值，新值覆盖旧值。
- `message = hello;` 是把值**拷贝**到另一个变量。

### 4. 命名规则
- 只能包含字母、数字、`$`、`_`；首字符不能是数字。
- `$` 和 `_` 是普通字符，无特殊含义（`let $ = 1; let _ = 2;` 合法）。
- 区分大小写：`apple` 与 `APPLE` 是两个变量。
- 允许非英文字符（如 `let 我 = '...'`），但**不推荐**，用英文是国际惯例。
- **保留字**不能作变量名：`let`、`class`、`return`、`function` 等。
- 多个单词用驼峰式（camelCase）：`myVeryLongName`。

### 5. 非严格模式下的隐式全局变量（坑）
- 没有 `"use strict"` 时，直接给未声明的变量赋值会自动创建它：`num = 5;` —— 糟糕的做法。
- 严格模式下报错：`ReferenceError: num is not defined`。

### 6. 常量：`const`
- `const` 声明后不能重新赋值，否则报错。
- 用于明确表达"这个值不会变"。

### 7. 常量命名约定
- **大写 + 下划线**：仅用于执行前就已知的"硬编码"值的别名，如 `const COLOR_RED = "#F00";`
- **常规驼峰命名**：运行时计算出来但赋值后不再改变的常量，如 `const pageLoadTime = ...;`

### 8. 命名的最佳实践
- 名称清晰、可读，描述所存的数据：`userName`、`shoppingCart`。
- 避免 `a`、`b`、`c` 这类无意义缩写；避免 `data`、`value` 这类等于什么都没说的名字（除非上下文非常明确）。
- 术语与团队保持一致（网站访客叫 user 就用 `currentUser`，不要 `currentVisitor`）。
- **不要为了省事复用变量装不同的东西**，多声明一个变量利大于弊，现代引擎和压缩器会优化，没有性能问题。

## 与 Java 对比
| Java | JS | 说明 |
|---|---|---|
| `String s = "x";` | `let s = "x";` | JS 声明时**不写类型**，变量可以随时装不同类型的值（动态类型） |
| `final int X = 1;` | `const X = 1;` | `const` 只是禁止**重新赋值**，如果值是对象，对象内部仍可修改（类似 Java `final` 引用） |
| 无 | `var` | Java 10 的 `var` 是类型推断，与 JS 的 `var` 毫无关系；JS 中不要再用 `var` |
| 未声明就使用 → 编译错误 | 非严格模式会隐式创建全局变量 | 用严格模式规避 |
| 保留字不能作变量名 | 同样 | 注意 JS 保留字列表与 Java 不同（如 `function`、`let`、`typeof`） |
| `$` 在标识符中合法但极少用 | `$`、`_` 常见 | jQuery 的 `$`、lodash 的 `_` 就是普通变量名 |

**实践建议**：默认用 `const`，需要重新赋值时才用 `let`，永远不用 `var`。

## 一句话总结
用 `let` 声明变量、`const` 声明常量、不用 `var`；命名用驼峰，硬编码常量用大写下划线；变量名要清晰描述内容。
