# 09 值的比较

> 原文：`zh.javascript.info/1-js/02-first-steps/09-comparison/article.md`

## 知识点

### 0. 比较运算符一览
| 含义 | 写法 |
|---|---|
| 大于 / 小于 | `a > b`、`a < b` |
| 大于等于 / 小于等于 | `a >= b`、`a <= b` |
| 相等（非严格） | `a == b`（注意 `=` 是赋值） |
| 不相等（非严格） | `a != b` |
| 严格相等 | `a === b` |
| 严格不相等 | `a !== b` |

### 1. 比较结果为 Boolean 类型
- 所有比较运算符都返回布尔值 `true` / `false`，可以赋给变量：

```js
alert( 2 > 1 );  // true
alert( 2 == 1 ); // false
alert( 2 != 1 ); // true

let result = 5 > 4;
alert( result ); // true
```

### 2. 字符串比较
- 按"字典（词典）顺序"**逐字符**比较：

```js
alert( 'Z' > 'A' );       // true
alert( 'Glow' > 'Glee' ); // true（G=G，l=l，o > e）
alert( 'Bee' > 'Be' );    // true（前缀相同，更长的更大）
```

- 算法：依次比较首字符，不相等则得出结果；相等则比较下一位；一方先用完字符则较短者小，同时用完则相等。
- **不是真正的字典顺序，而是 Unicode 编码顺序**：区分大小写，且小写字母的编码比大写大，所以 `'a' > 'A'` 为 `true`。

### 3. 不同类型间的比较
- 比较不同类型的值时，JS 先**把它们都转成数字**再比较：

```js
alert( '2' > 1 );   // true，'2' → 2
alert( '01' == 1 ); // true，'01' → 1
alert( true == 1 ); // true
alert( false == 0 ); // true
```

- **一个有趣的现象**：两个值 `==` 相等，但各自转布尔后结果相反。

```js
let a = 0;
alert( Boolean(a) ); // false

let b = "0";
alert( Boolean(b) ); // true

alert( a == b ); // true!
```

原因：`==` 走的是"转数字"规则（`"0"` → `0`），`Boolean()` 走的是布尔转换规则（非空字符串为真），两套规则相互独立。

### 4. 严格相等 `===`
- `==` 的问题：区分不出 `0` 和 `false`、`''` 和 `false`，因为两侧都被转成了数字 `0`。

```js
alert( 0 == false );  // true
alert( '' == false ); // true
```

- **`===` 不做任何类型转换**：类型不同直接返回 `false`。

```js
alert( 0 === false ); // false，类型不同
```

- 对应的严格不相等是 `!==`。
- 写起来略长，但意图清晰、不易出错。

### 5. 对 `null` 和 `undefined` 进行比较
三条规则：

| 比较方式 | 行为 |
|---|---|
| `null === undefined` | `false`，类型不同 |
| `null == undefined` | `true`，特殊规则：它们俩**只互相相等**，不等于任何其他值 |
| `< > <= >=` | 转成数字：`null` → `0`，`undefined` → `NaN` |

**奇怪的结果：`null` vs `0`**

```js
alert( null > 0 );  // (1) false
alert( null == 0 ); // (2) false
alert( null >= 0 ); // (3) true
```

- (1) 和 (3)：大小比较时 `null` 转成 `0`，所以 `0 > 0` 为 false，`0 >= 0` 为 true。
- (2)：`==` 对 `null/undefined` **不做类型转换**，有独立规则，`null` 只等于 `undefined`，所以 `null == 0` 为 false。
- 结论：`==` 与 `> < >= <=` 的逻辑是相互独立的，不能用数学直觉推断。

**特立独行的 `undefined`**

```js
alert( undefined > 0 );  // false (1)
alert( undefined < 0 );  // false (2)
alert( undefined == 0 ); // false (3)
```

- (1)(2)：`undefined` 转成 `NaN`，`NaN` 与任何值比较都是 `false`。
- (3)：`undefined` 只与 `null` 相等。

### 6. 避免问题
- 除了 `===` 之外，凡是有 `null/undefined` 参与的比较都要格外小心。
- 除非非常清楚自己在做什么，**永远不要用 `>= > < <=` 去比较可能为 `null/undefined` 的变量**；先单独检查它是否为 `null/undefined`，再做比较。

## 与 Java 对比
| Java | JS | 说明 |
|---|---|---|
| `==` 比较基本类型的值、引用类型的地址 | `==` 会做类型转换（转数字）后比较；`===` 不转换 | JS 的 `==` 是"宽松相等"，与 Java 的 `==` 语义完全不同，**默认用 `===`** |
| `"a".equals("b")` 比较字符串内容 | `'a' === 'b'` 直接比较内容 | JS 字符串是原始类型，`===` 就是比内容，不需要 `equals` |
| `"a".compareTo("b")` 比较字符串大小 | `'a' < 'b'` 直接用比较运算符 | 都是按 Unicode 码点逐字符比较 |
| `"2" > 1` 编译错误 | `'2' > 1` → `true` | JS 自动转数字 |
| `true == 1` 编译错误 | `true == 1` → `true`，`true === 1` → `false` | 布尔参与 `==` 转成 1/0 |
| `null == 0` 编译错误（类型不兼容） | `null == 0` → false，`null >= 0` → true | Java 编译期就拦住了，JS 运行时给出反直觉结果 |
| 对 `null` 调方法抛 NPE | `null/undefined` 参与比较不报错，悄悄转成 `0`/`NaN` | 错误不会暴露，需要主动防御 |
| 只有一种"空"：`null` | `null == undefined` 为 true，`null === undefined` 为 false | 需要同时判断两者时可以用 `x == null`（这是 `==` 唯一被普遍接受的用法） |

**实践建议**：
- **一律用 `===` 和 `!==`**，这是 JS 社区共识（ESLint `eqeqeq` 规则）。
- 唯一例外：`x == null` 可以同时判断 `null` 和 `undefined`，很多代码库接受这个写法；不接受的话就写 `x === null || x === undefined`。
- 对可能为 `null/undefined` 的变量，先判空再做大小比较。
- 字符串比较区分大小写，要忽略大小写先统一 `toLowerCase()`。

## 一句话总结
比较运算符返回布尔值；字符串按 Unicode 逐字符比较；不同类型比较时转数字，`==` 会转换而 `===` 不会，所以默认用 `===`；`null` 和 `undefined` 在 `==` 下只互相相等，在大小比较中分别变成 `0` 和 `NaN`，涉及它们的比较务必先判空。
