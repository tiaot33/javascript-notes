# 05 扩展内建类

> 原文：`zh.javascript.info/1-js/09-classes/05-extend-natives/article.md`
> 短文，两个知识点：`class X extends Array` 可以用，且内建方法会**自动返回子类实例**（可用 `Symbol.species` 调整）；内建类之间**不继承静态方法**，与用户代码 `extends` 的行为不同。

## 知识点

### 1. 可以直接 `extends` 内建类
```js
class PowerArray extends Array {
  isEmpty() { return this.length === 0; }
}

let arr = new PowerArray(1, 2, 5, 10, 50);
arr.isEmpty();                                // false

let filteredArr = arr.filter(item => item >= 10);
alert(filteredArr);                           // 10,50
filteredArr.isEmpty();                        // false ← filter 返回的也是 PowerArray！
```
- `Array`、`Map`、`Set`、`Error` 等都能被 `extends`，`length`、索引、`Array.isArray` 等行为都正常。
- 给几年前学过 JS 的人补一句：ES5 时代用 `Child.prototype = Object.create(Array.prototype)` 模拟继承 `Array` 是坏的（`length` 不会自动维护），**ES6 `class extends Array` 才真正可用**，因为派生构造器把创建对象的工作交给了内建的 `Array` 构造器（上一篇 `super()` 的机制）。

### 2. 内建方法返回子类实例的原理：`constructor` 与 `Symbol.species`
- `filter`、`map`、`slice`、`concat` 等内建方法在内部用 `arr.constructor` 来创建结果数组，而 `arr.constructor === PowerArray`，所以结果仍是 `PowerArray`，可以继续链式调用 `isEmpty()`。
- 精确地说，用的是 `arr.constructor[Symbol.species]`。给类加一个**静态 getter `Symbol.species`**，就能指定内建方法用哪个构造器造结果：

```js
class PowerArray extends Array {
  isEmpty() { return this.length === 0; }

  static get [Symbol.species]() {   // 内建方法将用它作为 constructor
    return Array;
  }
}

let arr = new PowerArray(1, 2, 5, 10, 50);
arr.isEmpty();                      // false，自己还是 PowerArray

let filteredArr = arr.filter(item => item >= 10);
filteredArr.isEmpty();              // Error: not a function ← 现在是普通 Array 了
```
- 什么时候想这么做：子类携带了额外状态或约束，不希望 `map/filter` 的派生结果"冒充"子类。
- `Map`、`Set`、`Promise`、`RegExp` 等也用 `Symbol.species`，机制相同。

### 3. 内建类之间没有静态方法继承
- 用户代码里 `class B extends A` 会设两条链，静态方法随 `B.__proto__ = A` 继承（上一篇）。
- **内建类是例外**：`Array.prototype.__proto__ === Object.prototype`（实例方法继承正常），但 **`Array.__proto__` 是 `Function.prototype` 而不是 `Object`**，所以没有 `Array.keys()`、`Date.keys()` 这种东西，`Object.keys` 只属于 `Object` 自己。
```
Object ──.prototype──▶ Object.prototype
  ✗ 二者之间没有 [[Prototype]] 连接      ▲ [[Prototype]]
Date   ──.prototype──▶ Date.prototype ────┘
```
- 这是"内建对象之间的继承"与"`extends` 继承"的一个重要区别。

## 与 Java 对比
| Java | JS | 说明 |
|---|---|---|
| `class MyList<E> extends ArrayList<E>` 可行 | `class PowerArray extends Array` 可行 | 都能扩展内建集合 |
| `myList.stream().filter(...).toList()` 返回 `List`，不是 `MyList` | `arr.filter(...)` 默认返回 `PowerArray` | JS 内建方法通过 `constructor[Symbol.species]` 保留子类型，Java 需 `Collectors.toCollection(MyList::new)` 手动指定 |
| 无对应机制 | `static get [Symbol.species]() { return Array; }` 让派生结果退回基类 | "虚拟构造器"钩子，Java 里没有 |
| `String`、`Integer` 等是 `final`，不能继承 | 原始值不可继承，包装类 `String`/`Number` 技术上可 `extends`（极少这么做） | 都不建议 |
| 静态方法通过子类名可见（编译期解析到声明类） | `Array.__proto__ === Function.prototype`，`Array` 拿不到 `Object` 的静态方法 | Java 静态方法"看起来"可沿类层次访问，JS 内建类之间彻底没有这层关系 |
| 自定义异常 `class MyEx extends RuntimeException` | `class MyError extends Error` 同样常见 | 后续"错误处理"章节会讲 |

## 一句话总结
`class PowerArray extends Array` 这类扩展内建类在 ES6 后完全可用，且 `filter/map/slice` 等内建方法会通过 `this.constructor[Symbol.species]` 用**子类**构造结果，让扩展方法可以链式传递；若希望派生结果退回普通 `Array`，给类加静态 getter `static get [Symbol.species]() { return Array; }`（`Map/Set` 同理）；内建类之间只有 `X.prototype → Object.prototype` 的实例方法继承，`Array.__proto__` 是 `Function.prototype` 而非 `Object`，所以**没有静态方法继承**，这与用户代码 `extends` 设置两条链的行为不同。
