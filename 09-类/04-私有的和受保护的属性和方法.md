# 04 私有的和受保护的属性和方法

> 原文：`zh.javascript.info/1-js/09-classes/04-private-protected-properties-methods/article.md`
> 封装。Java 有 `private/protected/public` 加包级私有四级访问控制，JS 只有两样东西：**`#` 私有字段（语言强制）**和**`_` 前缀约定（纯君子协定）**，没有语言级的 `protected`。教程用咖啡机做类比：内部接口（锅炉、加热管）藏起来，外部接口（按钮、显示屏）暴露。

## 知识点

### 1. 内部接口 vs 外部接口
- **内部接口**：只供类的其他方法使用的属性/方法。
- **外部接口**：类外部也能用的属性/方法。
- JS 对象字段分两种：**公共的**（到处可访问，构成外部接口）和**私有的**（只能在类内部访问）。
- 其他语言常见的**受保护的**（类内部 + 子类可访问）JS 没有语言级实现，靠约定模拟。实践中它反而是用得最多的一种。

### 2. 受保护的属性：`_` 前缀约定 + 访问器控制
```js
class CoffeeMachine {
  _waterAmount = 0;                 // 约定：下划线开头 = 内部属性，外部别碰

  set waterAmount(value) {
    if (value < 0) value = 0;       // 加校验
    this._waterAmount = value;
  }
  get waterAmount() { return this._waterAmount; }

  constructor(power) { this._power = power; }
}

let coffeeMachine = new CoffeeMachine(100);
coffeeMachine.waterAmount = -10;    // _waterAmount 变为 0
```
- `_xxx` **不受语言限制**，`coffeeMachine._waterAmount = -1` 照样能写，只是大家约定不这么做。
- 受保护字段**天然可被子类访问**：`class MegaMachine extends CoffeeMachine` 里随便用 `this._waterAmount`。

### 3. 只读属性：只给 getter 不给 setter
```js
class CoffeeMachine {
  constructor(power) { this._power = power; }
  get power() { return this._power; }   // 没有 setter
}
coffeeMachine.power = 25; // 严格模式（模块/类体内）TypeError；非严格脚本里静默忽略
```
- 适合"创建时确定、之后不变"的属性。
- 教程注释写的是 Error，准确说：赋值发生在**严格模式**代码中才抛 `TypeError`，在非严格的普通脚本里是静默失败（回顾 07 章）。

### 4. `get/set` 访问器 vs `getX()/setX()` 方法
```js
class CoffeeMachine {
  _waterAmount = 0;
  setWaterAmount(value) { if (value < 0) value = 0; this._waterAmount = value; }
  getWaterAmount() { return this._waterAmount; }
}
new CoffeeMachine().setWaterAmount(100);
```
- 教程观点：**多数时候更倾向 `getX()/setX()` 函数**，因为函数更灵活（可接多个参数）；`get/set` 语法更短。没有硬性规定，自行取舍。
- 对 Java 开发者：两种风格都合法，团队内统一即可。

### 5. 私有的 `#field` / `#method()`：语言强制
```js
class CoffeeMachine {
  #waterLimit = 200;                        // 私有字段
  #waterAmount = 0;

  #fixWaterAmount(value) {                  // 私有方法
    if (value < 0) return 0;
    if (value > this.#waterLimit) return this.#waterLimit;
    return value;
  }

  setWaterAmount(value) { this.#waterAmount = this.#fixWaterAmount(value); }
}
// 教程原代码有两处笔误（#fixWaterAmount 漏了兜底 return、结果写进了 #waterLimit），上面已修正

let m = new CoffeeMachine();
m.#fixWaterAmount(123); // SyntaxError
m.#waterLimit = 1000;   // SyntaxError
```
- `#` 是名字的一部分，`#waterAmount` 与 `waterAmount` **互不冲突**，常见模式是私有字段 + 同名公开访问器：

```js
class CoffeeMachine {
  #waterAmount = 0;
  get waterAmount() { return this.#waterAmount; }
  set waterAmount(value) { if (value < 0) value = 0; this.#waterAmount = value; }
}
```
- **子类也访问不到**父类的 `#field`：`class Mega extends CoffeeMachine { m() { this.#waterAmount } }` 是语法错误，只能走父类暴露的 getter/setter。很多场景这限制过于严格，所以实践中受保护的 `_` 用得更多。
- **不能用 `this[name]` 动态访问**：`this['#name']` 拿不到私有字段，这是保证私有性的语法限制。
- 私有名对反射也不可见：`Object.keys`、`Object.getOwnPropertyNames`、`JSON.stringify` 都看不到 `#` 字段。
- 对一个不是本类实例的对象访问 `obj.#x` 会抛 `TypeError`，私有字段是"按类"绑定的，不是按对象形状。
- 补充：教程写"即将进入规范、浏览器支持不佳"已经过时，私有字段/方法在 **ES2022** 定稿，现代浏览器和 Node 12+ 全部原生支持。ES2022 还提供 `#x in obj` 用于检查某对象是否拥有该私有字段。

### 6. 为什么要封装（教程总结）
1. **保护使用者不误伤自己**：内部细节暴露出去，总有人会去改，然后坏掉。
2. **可维护性**：严格界定内部接口后，类的作者可以自由重命名/删除内部成员而无需通知使用者，只要外部接口不变。
3. **隐藏复杂性**：简单、有文档的外部接口 + 藏起来的实现，用起来才轻松。

## 与 Java 对比
| Java | JS | 说明 |
|---|---|---|
| `private` 字段：本类可见，子类不可见 | `#field`：本类可见，子类不可见 | 语义基本一致，JS 甚至更严：**反射也拿不到** |
| `protected`：本类 + 子类 + 同包 | 无语言支持，`_field` 约定 | JS 里"受保护"全靠自觉，工具（ESLint、TypeScript）可辅助 |
| `public` 外部接口 | 不加前缀的普通属性 | 一致 |
| 包级私有（默认可见性） | 无 | 模块作用域可部分替代：不 export 就是模块私有 |
| 编译期检查访问权限 | `#` 访问违规是 **SyntaxError**（解析期），`_` 完全不检查 | `#` 比 Java 更早发现问题 |
| 反射 `setAccessible(true)` 可绕过 `private` | `#` 无法绕过，没有任何 API 能读到 | 真正的硬私有 |
| 私有字段按声明类区分 | `#x` 按类绑定，对非本类实例访问抛 `TypeError` | 一致 |
| `getX()/setX()` 是唯一选择 | `get x()/set x()` 或 `getX()/setX()` 二选一 | 教程建议函数更灵活，看团队约定 |
| 只读：`final` 字段 + 只有 getter | 只写 getter 不写 setter | 一致，但 JS 只在严格模式下报错 |

## 一句话总结
JS 的封装只有两件工具：`#field` / `#method()` 是**语言强制的私有**（ES2022 已定稿），只能在定义它的类体内通过 `this.#x` 访问，子类、外部、`this[name]`、反射统统不行，且与同名公开属性不冲突；`_field` 是**约定上的受保护**，语言不做任何限制，但子类可自然访问，因此实践中比 `#` 更常用；只读属性靠"只给 getter 不给 setter"实现（严格模式下赋值抛错）；`get/set` 访问器与 `getX()/setX()` 方法都可以，后者能接多个参数更灵活。封装的价值是保护使用者、允许内部自由重构、隐藏复杂性。
