# 02 类继承

> 原文：`zh.javascript.info/1-js/09-classes/02-class-inheritance/article.md`
> `extends` / `super` 表面上与 Java 几乎一样，底层仍是原型链，且有两处 Java 开发者一定会撞上的差异：**派生类构造器必须先 `super()` 再碰 `this`**，以及**类字段重写的诡异时序**。后半部分的 `[[HomeObject]]` 解释了 `super` 为什么能工作，属进阶内容。

## 知识点

### 1. `extends`：本质是设置原型链
```js
class Animal {
  constructor(name) { this.speed = 0; this.name = name; }
  run(speed) { this.speed = speed; alert(`${this.name} runs with speed ${this.speed}.`); }
  stop() { this.speed = 0; alert(`${this.name} stands still.`); }
}

class Rabbit extends Animal {
  hide() { alert(`${this.name} hides!`); }
}

let rabbit = new Rabbit("White Rabbit");
rabbit.run(5);  // 来自 Animal.prototype
rabbit.hide();  // 来自 Rabbit.prototype
```
- `extends` 做的事：**`Rabbit.prototype.[[Prototype]] = Animal.prototype`**。查找 `rabbit.run` 的路径：`rabbit` → `Rabbit.prototype`（没有）→ `Animal.prototype`（找到）。
- 内建对象同理：`Date.prototype.[[Prototype]] === Object.prototype`。
- `extends` 后面可以是**任意表达式**，只要求值结果是类/构造函数即可，例如返回类的函数调用：

```js
function f(phrase) {
  return class { sayHi() { alert(phrase); } };
}
class User extends f("Hello") {}
new User().sayHi(); // Hello
```

### 2. 重写方法与 `super.method()`
- 子类同名方法直接遮蔽父类方法（原型链就近原则）。
- 想"在父类逻辑基础上加点东西"用 `super.method(...)`；调用父类构造器用 `super(...)`（只能在 constructor 里）。

```js
class Rabbit extends Animal {
  hide() { alert(`${this.name} hides!`); }
  stop() {
    super.stop(); // 先调父类 stop
    this.hide();  // 再 hide
  }
}
```
- **箭头函数没有自己的 `super`**，会取外层方法的 `super`，所以 `setTimeout(() => super.stop(), 1000)` 能正常工作；换成 `function() { super.stop() }` 则是语法错误。

### 3. 重写 constructor：必须先 `super()`
没写 constructor 的派生类，会自动生成：
```js
constructor(...args) { super(...args); }   // 把所有参数原样转给父类
```
自己写 constructor 时：

```js
class Rabbit extends Animal {
  constructor(name, earLength) {
    this.speed = 0;      // ❌ ReferenceError（教程写作 "this is not defined"，
    this.name = name;    //    现代引擎提示 "Must call super constructor in derived class before accessing 'this'"）
    this.earLength = earLength;
  }
}
```
**规则：派生类的 constructor 必须调用 `super(...)`，且必须在使用 `this` 之前。**

原因：派生类构造器带内部标记 `[[ConstructorKind]]: "derived"`。
- 普通构造函数被 `new` 时：自己创建空对象并赋给 `this`。
- 派生构造器被 `new` 时：**不创建 `this`**，它期望由父类构造器（最终由最顶层的基类）来创建。`super()` 就是去执行父类构造器并拿回 `this`。

正确写法：
```js
class Rabbit extends Animal {
  constructor(name, earLength) {
    super(name);              // 父类创建并初始化 this
    this.earLength = earLength;
  }
}
```
练习题 `ExtendedClock` 就是这个模式：`super(options)` 之后再解构自己的参数 `let { precision = 1000 } = options; this.precision = precision;`，然后重写 `start()` 使用 `this.precision`。

### 4. 重写类字段的诡异时序（高阶要点）
```js
class Animal {
  name = 'animal';
  constructor() { alert(this.name); } // (*)
}
class Rabbit extends Animal {
  name = 'rabbit';
}
new Animal(); // animal
new Rabbit(); // animal  ← 不是 rabbit！
```
而换成方法就"正常"了：父类构造器里 `this.showName()` 会调到子类重写的版本，输出 `rabbit`。

原因在于**类字段的初始化时机**：
- 基类：字段在 constructor 执行**之前**初始化。
- 派生类：字段在 **`super()` 返回之后立刻**初始化。

`new Rabbit()` → 隐式 constructor 调 `super()` → 执行 `Animal` 的字段初始化（`name = 'animal'`）和构造器体（此时 `Rabbit` 的字段还没赋值，`this.name` 是 `'animal'`）→ `super()` 返回 → 才执行 `Rabbit` 的字段初始化把 `name` 覆盖为 `'rabbit'`。

- 只有"父类构造器使用了被子类重写的字段"时才会显现，不常见但一旦出现很难查。
- 修法：需要被父类构造器"看到"的可变点，用**方法或 getter/setter**而不是字段。
- 同一时序还导致另一种情况：父类构造器调用子类重写的方法，方法里读子类字段，读到的是 `undefined`（子类字段还没初始化）。这与 Java "不要在构造器里调用可被重写的方法"是同一个坑。

### 5. 深入：`super` 为什么不能靠 `this` 实现（进阶）
朴素想法：`super.method()` ≈ `this.__proto__.method.call(this)`。两层继承时可行，三层就死循环：

```js
let animal  = { name: "Animal", eat() { alert(`${this.name} eats.`); } };
let rabbit  = { __proto__: animal, eat() { this.__proto__.eat.call(this); } }; // (*)
let longEar = { __proto__: rabbit, eat() { this.__proto__.eat.call(this); } }; // (**)

longEar.eat(); // Error: Maximum call stack size exceeded
```
- 无论在哪一层，`this` 都是 `longEar`，于是 `this.__proto__` 永远是 `rabbit`，`(*)` 行反复调用 `rabbit.eat` 自己，无法沿链上溯。
- 结论：只凭 `this` 无法知道"当前方法定义在链的哪一层"。

### 6. `[[HomeObject]]`：`super` 的真正实现
- 函数被**定义为类方法或对象方法**时，会获得内部属性 `[[HomeObject]]` = 定义它的那个对象/类原型。
- `super.method()` 的解析：**`[[HomeObject]].[[Prototype]].method`**，与 `this` 无关，所以多层链也正确。

```js
let animal  = { name: "Animal",   eat() { alert(`${this.name} eats.`); } };   // [[HomeObject]] = animal
let rabbit  = { __proto__: animal, name: "Rabbit",   eat() { super.eat(); } }; // [[HomeObject]] = rabbit
let longEar = { __proto__: rabbit, name: "Long Ear", eat() { super.eat(); } }; // [[HomeObject]] = longEar
longEar.eat(); // Long Ear eats.
```

两个推论：

**（a）带 `super` 的方法不再"自由"。** JS 函数本来可以随意复制到别的对象上用另一个 `this` 调用；但 `[[HomeObject]]` 一经设定不可更改，方法"记住"了出生地。不用 `super` 的方法仍可自由复制，用了 `super` 的复制后会指错父类：

```js
let animal = { sayHi() { alert(`I'm an animal`); } };
let rabbit = { __proto__: animal, sayHi() { super.sayHi(); } };
let plant  = { sayHi() { alert("I'm a plant"); } };
let tree   = { __proto__: plant, sayHi: rabbit.sayHi };  // 复制过来

tree.sayHi(); // I'm an animal (?!)  ← super 沿 rabbit 的原型链找到 animal，而不是 plant
```

**（b）必须用方法简写语法。** `[[HomeObject]]` 只为 `method() {...}` 形式设置；`method: function() {...}` 形式没有 `[[HomeObject]]`，里面写 `super` 直接是**语法错误**（解析阶段就报）。

```js
let rabbit = {
  __proto__: animal,
  eat: function() { super.eat(); } // SyntaxError: 'super' keyword unexpected here
};
```

## 与 Java 对比
| Java | JS | 说明 |
|---|---|---|
| `extends` 建立类型层次，编译期固定 | `extends` 设置 `Child.prototype.__proto__ = Parent.prototype`（另外还有 `Child.__proto__ = Parent`，下一篇讲） | 语法一样，底层还是原型链 |
| 构造器没写 `super(...)`，编译器在第一行插入 `super()` | 没写 constructor 时自动生成 `constructor(...args) { super(...args); }`；**写了 constructor 就必须自己调** | Java 是"帮你插一句"，JS 是"没写构造器才帮你写整个构造器" |
| `super()` 必须是构造器第一条语句（Java 25 前的正式规则） | `super()` 前不能碰 `this`，但**可以执行不涉及 `this` 的代码**（如参数计算） | JS 更宽松一点，本质要求相同 |
| `super.method()` 调父类实现 | 同 | 一致 |
| `super` 静态绑定：编译期确定父类 | `super` 通过 `[[HomeObject]]` 静态绑定到定义处 | 结果相同；JS 因函数可复制而多出"复制带 super 的方法会指错"的坑 |
| 父类构造器里调用被重写的方法，看到子类方法但子类字段还是默认值 | 同样：子类字段在 `super()` 返回后才初始化，此时读到 `undefined` | 同一个经典坑；JS 额外多一条：父类构造器读**字段**总是读到父类自己的值 |
| 同名字段是两个独立的存储（field hiding） | 同名字段是同一个属性，子类初始化时覆盖父类值 | 机制不同，`new Rabbit()` 输出 `animal` 的结果却一致 |
| lambda 里可用外层的 `super` | 箭头函数没有自己的 `super`，透明地取外层 | 一致 |
| `extends` 后只能写类名 | `extends` 后可以写任意表达式 | JS 可以按条件动态选择父类 |

## 一句话总结
`class Child extends Parent` 把 `Child.prototype` 的原型设为 `Parent.prototype`，方法就近遮蔽，`super.method()` 调父类实现；派生类构造器带 `derived` 标记，不会自己创建 `this`，所以**必须在使用 `this` 之前调用 `super(...)`**（不写构造器则自动生成透传参数的版本）；类字段在派生类里于 `super()` 返回后才初始化，因此父类构造器读到的永远是父类字段值，需要多态的地方用方法而不是字段；`super` 的实现依赖方法定义时记录的 `[[HomeObject]]` 而非 `this`，所以只有 `method() {}` 简写语法能用 `super`，且带 `super` 的方法复制到别的对象上会指向错误的父类。
