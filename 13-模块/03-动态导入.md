# 03 动态导入

> 原文：`zh.javascript.info/1-js/13-modules/03-modules-dynamic-imports/article.md`
> 静态 `import` 是编译期的"硬编码"，动态 `import()` 是运行时的"按需加载"——类似 Java 里 `Class.forName()` + 反射 对比 编译期 `import` 的关系。

## 知识点

### 1. 静态 import 的两个限制

前面学的导出和导入语句称为"**静态**"导入，语法严格：

1. **模块路径必须是原始类型字符串**，不能是函数调用或动态拼出来的值：

```js
import ... from getModuleName(); // Error, only from "string" is allowed
```

2. **不能按条件或在运行时导入**，`import` 不能放进任何块：

```js
if (...) {
  import ...; // Error, not allowed!
}
{
  import ...; // Error, we can't put import in any block
}
```

**为什么限制这么死？** `import`/`export` 的作用是提供**代码结构的主干**：结构简单固定，工具才能静态分析——收集模块打包进一个文件、tree-shaking 删掉未使用的导出，这些优化全都依赖静态可分析性。

### 2. `import(module)` 表达式

按需动态加载的解决方案：

- `import(module)` **加载模块并返回一个 promise**，该 promise resolve 为一个包含其所有导出的**模块对象**；
- 可以在代码中的**任意位置**调用（if 里、函数里都行）。

两种消费姿势：

```js
// then/catch
let modulePath = prompt("Which module to load?");
import(modulePath)
  .then(obj => /* module object */)
  .catch(err => /* loading error, e.g. if no such module */)

// async 函数里用 await
let module = await import(modulePath);
```

### 3. 拿到导出：命名导出 vs 默认导出

```js
// 📁 say.js
export function hi() { alert(`Hello`); }
export function bye() { alert(`Bye`); }

// 命名导出：直接解构模块对象
let {hi, bye} = await import('./say.js');
hi();
bye();
```

```js
// 📁 say.js 若是默认导出
export default function() {
  alert("Module loaded (export default)!");
}

// 默认导出在模块对象的 default 属性上
let obj = await import('./say.js');
let say = obj.default;
// 或一行解构（注意语法：default 作 key，改名给 say）
let {default: say} = await import('./say.js');
say();
```

### 4. 两个注意点

- **动态导入在常规脚本中也能工作**，不需要 `script type="module"`。
- **`import()` 不是函数**：虽然长得像函数调用，但它是一种特殊语法（类似 `super()` 只是恰好用了括号）。因此**不能**把它复制到变量里，也不能对它用 `call/apply`：

```js
let f = import; // 不行
import.call(...); // 不行
```

## 与 Java 对比

| Java | JS | 说明 |
|---|---|---|
| 编译期 `import`，写死 | 静态 `import`，路径必须是字面量字符串 | 静态可分析是打包优化（tree-shaking）的前提 |
| `Class.forName(name)` + 反射，运行时按名字加载 | `import(modulePath)` 返回 promise | 都是运行时按需加载；JS 的返回值是模块对象（含全部导出） |
| `ServiceLoader` 按配置动态装配实现 | `import()` 配 if/条件逻辑 | 插件化、按需加载场景一致 |
| — | `import()` 是语法不是函数 | 不能赋给变量、不能 `call/apply`，别被括号骗了 |

## 一句话总结

静态 `import` 路径必须是字面量、必须顶层——为了静态分析和打包优化；需要按条件/运行时加载时用 `import(module)`：它返回 resolve 成模块对象的 promise，用 `await` 或 `.then` 消费，命名导出直接解构、默认导出取 `.default`；它在普通脚本里也能用，但本质是语法而非函数。
