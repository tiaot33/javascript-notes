# 01 简介：回调

> 原文：`zh.javascript.info/1-js/11-async/01-callbacks/article.md`
> 全文都在讲"为什么需要 Promise"：回调本身没问题，问题是**串联多个异步操作时的嵌套金字塔**。Java 开发者可类比 `CompletableFuture` 出现之前的 `Future` + 监听器时代。

## 知识点

### 1. 背景：异步行为由宿主环境提供

- `setTimeout`、加载脚本（`<script src>`）等都是**异步**的：发起后立即返回，完成在将来的某个时刻。
- 异步调用下面的代码**不会等待**它完成：

```js
loadScript('/my/script.js'); // 脚本里有 function newFunction() {...}
newFunction(); // 报错！脚本可能还没加载完
```

### 2. 基于回调（callback）的异步风格

给异步函数传一个函数，行为完成时由它调用：

```js
function loadScript(src, callback) {
  let script = document.createElement('script');
  script.src = src;
  script.onload = () => callback(script); // 加载完成后执行回调
  document.head.append(script);
}

loadScript('/my/script.js', function() {
  newFunction(); // 在回调里使用脚本中的东西，保证时序正确
});
```

约定：异步函数提供一个 `callback` 参数，在相应事件完成时调用。

### 3. Error 优先回调（error-first callback）

加载可能失败，错误也要传给回调。业界约定（Node.js 风格）：

1. `callback` 的**第一个参数留给 error**：出错时 `callback(err)`；
2. 第二个（及之后）参数放成功结果：成功时 `callback(null, result1, result2…)`。

```js
function loadScript(src, callback) {
  let script = document.createElement('script');
  script.src = src;
  script.onload = () => callback(null, script);
  script.onerror = () => callback(new Error(`Script load error for ${src}`));
  document.head.append(script);
}

loadScript('/my/script.js', function(error, script) {
  if (error) { /* 处理 error */ }
  else { /* 加载成功 */ }
});
```

单一回调同时承担报错和传结果两个职责。

### 4. 厄运金字塔（callback hell）

多个异步行为**一个接一个**执行时，每个新行为都要写在前一个的回调里：

```js
loadScript('1.js', function(error, script) {
  if (error) { handleError(error); }
  else {
    loadScript('2.js', function(error, script) {
      if (error) { handleError(error); }
      else {
        loadScript('3.js', function(error, script) {
          if (error) { handleError(error); }
          else { /* ...加载完所有脚本后继续 */ }
        });
      }
    });
  }
});
```

- 每多一步嵌套就向右长一层，配上真实的循环/条件代码后迅速失控。
- 又名"回调地狱" / "厄运金字塔"（pyramid of doom）。

### 5. 拆成独立函数 ≠ 好方案

```js
loadScript('1.js', step1);
function step1(error, script) { /* ... */ loadScript('2.js', step2); }
function step2(error, script) { /* ... */ loadScript('3.js', step3); }
function step3(error, script) { /* ... */ }
```

- 消除了深层嵌套，但代码被"撕裂"：阅读时要在各函数间跳转；
- `step*` 都是一次性函数，只为避免金字塔而存在，污染命名空间。

→ 需要更好的方案，即下一篇的 **Promise**。

## 与 Java 对比

| Java | JS | 说明 |
|---|---|---|
| 监听器接口 / 匿名内部类（Swing、Servlet 时代） | 回调函数（一等公民，直接传） | JS 函数天然可传递，无需 SAM 接口这层皮 |
| `Future.get()` 阻塞等待结果 | 不能"等"，只能注册回调 | JS 单线程，阻塞主线程会冻结页面，所以异步全靠回调/事件 |
| `ListenableFuture` 的 `onSuccess/onFailure` 双回调 | error-first 回调：`callback(err, result)` 单回调，首参为 error | Node.js 奠定的约定，同一种信息的两种打包法 |
| 嵌套回调地狱 → `CompletableFuture` 链式解决 | 回调地狱 → Promise（下篇） | 两语言走了完全相同的历史路径 |

## 一句话总结

回调是 JS 异步的原始形态：异步函数约定一个"完成时调用"的函数参数，error-first 约定用 `callback(err, result)` 同时传递成败；一旦需要串联多个异步步骤，嵌套就会形成"厄运金字塔"，拆函数也只是把问题从"深"变成"散"——这正是 Promise 要解决的问题。
