# 07 微任务（Microtask）

> 原文：`zh.javascript.info/1-js/11-async/07-microtask-queue/article.md`
> 解释一个反直觉现象：**promise 的处理程序永远是异步的，哪怕 promise 早已 settled**。机制就是微任务队列；它同时解释了 `unhandledrejection` 的触发时机。

## 知识点

### 1. 反直觉现象

```js
let promise = Promise.resolve();

promise.then(() => alert("promise done!"));

alert("code finished"); // 先显示它！然后才是 "promise done!"
```

promise 明明立刻就 resolve 了，`.then` 的处理程序却仍排在同步代码**之后**执行。

### 2. 微任务队列（microtask queue）

ECMA 标准规定的内部队列 `PromiseJobs`（V8 术语"微任务队列"）：

- **先进先出**：先入队的先执行；
- **只在 JS 引擎手头没有别的代码在运行时**，才开始执行队列中的任务。

即：promise 就绪时，它的 `.then/catch/finally` 处理程序**入队但不立即执行**；当前同步代码跑完后，引擎才从队列取任务执行。所以上例 `"code finished"` 先出现。

### 3. 链上每一环都过一次队列

含多个 `.then/catch/finally` 的链中，每个处理程序都是独立异步执行的：先入队，等当前代码完成、且先前排队的处理程序都完成后才执行。

**要保证顺序，就把代码放进链里**：

```js
Promise.resolve()
  .then(() => alert("promise done!"))
  .then(() => alert("code finished")); // 现在顺序符合预期
```

### 4. 微任务队列解释 `unhandledrejection` 的触发时机

**"未处理的 rejection"在微任务队列清空时被判定**：此时引擎检查 promise，凡仍处于 rejected 且无人处理的，触发 `unhandledrejection`。

```js
let promise = Promise.reject(new Error("Promise Failed!"));
setTimeout(() => promise.catch(err => alert('caught')), 1000); // 迟到的 .catch

// 输出顺序：先 "Promise Failed!"（unhandledrejection），后 "caught"
window.addEventListener('unhandledrejection', event => alert(event.reason));
```

为什么先触发 `unhandledrejection`？因为 `setTimeout` 里的 `.catch` 是**宏任务**，要等 1 秒后才挂到 promise 上；而微任务队列在当前脚本跑完时即清空，此刻 promise 仍无处理程序 → 事件触发。迟到的 `.catch` 改不了既成事实。

### 5. 与宏任务的关系（预告）

微任务概念与"事件循环（event loop）""宏任务（macrotask）"紧密相关（`setTimeout` 就是宏任务），将在 <info:event-loop> 一章展开。先记住执行序：**同步代码 → 清微任务队列 → 下一个宏任务 → 再清微任务队列 → ……**

## 与 Java 对比

| Java | JS | 说明 |
|---|---|---|
| 多线程，任务提交给 `Executor` 后何时跑取决于调度 | 单线程事件循环，异步回调排进队列严格按序执行 | JS 没有竞态，但有"队列顺序"这门新学问 |
| `CompletableFuture.thenApply` 默认在完成线程里**同步**执行回调 | `.then` 处理程序**永远异步**（经微任务队列） | 重要差异：JS 里不存在"回调在 resolve 的同一线程栈里立即跑"的情况 |
| — | 微任务优先于宏任务（渲染、`setTimeout`） | 微任务队列清空后才轮到下一个宏任务/渲染 |

## 一句话总结

`.then/catch/finally` 的处理程序永远异步：promise 就绪时它们进入先进先出的**微任务队列**，等当前同步代码执行完才依次执行——所以想让代码"在 promise 之后跑"就得把它接进链里；`unhandledrejection` 在微任务队列清空时判定，`setTimeout`（宏任务）里迟挂的 `.catch` 拦不住它。
