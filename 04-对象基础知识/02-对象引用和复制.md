# 02 对象引用和复制

> 原文：`zh.javascript.info/1-js/04-object-basics/02-object-copy/article.md`

## 知识点

### 1. 对象按引用存储和复制
- 原始类型（字符串、数字、布尔）赋值时**整体拷贝**。
- **对象变量存的不是对象本身，而是对象在内存中的地址（引用）**。

```js
let user = { name: "John" };
let admin = user;   // 复制的是引用，对象只有一个！

admin.name = "Pete";
alert(user.name);   // 'Pete' —— 两个变量指向同一个对象
```

### 2. 通过引用比较
- 仅当两个变量引用**同一个对象**时才相等：

```js
let a = {};
let b = a;
a === b; // true

let c = {};
let d = {};
c === d; // false —— 即使都是空对象，内容相同也不相等
```
- **JS 没有 Java 的 `equals()` 概念**，`==` / `===` 对对象都是比引用。

### 3. 浅拷贝：Object.assign
想真正复制一个对象，需要逐属性拷贝：

```js
// 手写版
let clone = {};
for (let key in user) clone[key] = user[key];

// 等价的标准方法
let clone = Object.assign({}, user);
```
`Object.assign(dest, src1, src2, ...)`：
- 把所有源对象的属性拷贝到 `dest` 并返回 `dest`。
- 同名属性**后者覆盖前者**。
- 常用于合并对象：`Object.assign(user, permissions1, permissions2)`。
- 也可用扩展语法 `let clone = {...user}`（后续章节讲）。

### 4. 深层克隆
- `Object.assign` 是**浅拷贝**：属性值若是对象，拷贝的还是引用，两边共享嵌套对象：

```js
let user = { name: "John", sizes: { height: 182, width: 50 } };
let clone = Object.assign({}, user);

user.sizes === clone.sizes; // true，嵌套对象被共享！
user.sizes.width++;
clone.sizes.width;          // 51，互相影响
```

#### 深拷贝的代码实现方式

**1. 现代原生标准：`structuredClone(obj)`（推荐）**
现代浏览器与 Node.js 17+ 已原生内置，不需要引入任何第三方库：

```js
let user = { name: "John", sizes: { height: 182, width: 50 } };

let clone = structuredClone(user);

user.sizes.width++;
alert(user.sizes.width);  // 51
alert(clone.sizes.width); // 50 —— 彻底隔离，互不影响！

// 支持循环引用：
user.me = user;
let clone2 = structuredClone(user);
alert(clone2.me === clone2); // true
```
> **限制**：属性值中如果包含**函数**或 **DOM 节点**等复杂对象时会报错（抛出 `DOMException`）。

**2. 简易方案：`JSON.parse(JSON.stringify(obj))`**
纯数据对象常用的简易手段：

```js
let user = { name: "John", sizes: { height: 182, width: 50 } };
let clone = JSON.parse(JSON.stringify(user));
```
> **限制**：
> - 会直接忽略 `undefined`、函数、`Symbol` 属性。
> - `Date` 对象会被转为 ISO 字符串，`RegExp` / `Set` / `Map` 会丢失结构。
> - **不支持循环引用**（会报错 `TypeError: Converting circular structure to JSON`）。

**3. 第三方库：lodash 的 `_.cloneDeep(obj)`（最稳健通用）**
工业级完备方案，能处理各种边界类型：

```js
// 需要 npm i lodash 或引入 lodash.js
const _ = require("lodash"); // 或 import cloneDeep from "lodash/cloneDeep";

let user = { name: "John", sizes: { height: 182, width: 50 } };
let clone = _.cloneDeep(user);
```

### 5. const 声明的对象可以修改内容
```js
const user = { name: "John" };
user.name = "Pete"; // 合法！const 锁住的只是"引用"本身
user = {};          // TypeError —— 整体重新赋值才报错
```

## 与 Java 对比
| Java | JS | 说明 |
|---|---|---|
| 对象变量存引用，`=` 复制引用 | 完全一样 | 心智模型可直接迁移 |
| `==` 比引用，`equals()` 比内容 | `==`/`===` 都只比引用，**语言层面没有 equals** | 需要深比较得自己写或用 lodash `_.isEqual` |
| `Cloneable` / `clone()` | `Object.assign({}, obj)` 或 `{...obj}` | 都是浅拷贝 |
| 深拷贝：序列化/手写/commons-lang `SerializationUtils.clone` | 原生 `structuredClone(obj)` / lodash `_.cloneDeep(obj)` | 现代 JS 已内置原生深拷贝，复杂边界用 lodash |
| `final User user`：引用不可变，内容可变 | `const user`：语义完全一致 | const ≠ 不可变对象 |

**实践建议**：
- 修改函数收到的对象参数会影响调用方（引用语义），与 Java 相同，要有防御意识。
- 拷贝前先想清楚要浅拷贝还是深拷贝；嵌套结构浅拷贝后共享内部对象，是常见 bug 来源。

## 一句话总结
对象变量存的是引用，赋值/比较/传参全都围绕引用；`Object.assign` 和 `{...obj}` 是浅拷贝，嵌套对象要深拷贝（原生 `structuredClone` 或 lodash `_.cloneDeep`）；`const` 只锁引用不锁内容。
