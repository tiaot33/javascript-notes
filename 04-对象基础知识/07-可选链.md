# 07 可选链 "?."

> 原文：`zh.javascript.info/1-js/04-object-basics/07-optional-chaining/article.md`

## 知识点

### 1. 要解决的问题
访问嵌套属性时，中间环节为 `null/undefined` 会直接报错（类似 Java 的 NPE）：

```js
let user = {}; // 没有 address
user.address.street; // TypeError: Cannot read properties of undefined

document.querySelector('.elem').innerHTML; // 元素不存在返回 null → 报错
```
老式防御写法，层层判空，又丑又重复：

```js
user.address ? user.address.street : undefined
user.address && user.address.street && user.address.street.name
```

### 2. `?.`：左边是 `null/undefined` 就短路返回 `undefined`
```js
let user = {};
user?.address?.street; // undefined，不报错

let html = document.querySelector('.elem')?.innerHTML; // 没有该元素 → undefined
```
- 判定标准**只有 `null` 和 `undefined`**（不是其他假值！`0`、`""`、`false` 都会正常继续）。
- `?.` **只让它前面的一环变成可选**，后面的属性仍是常规访问：

```js
user?.address.street.name
// 只容忍 user 为 null/undefined；
// 若 user.address 不存在，照样报错！要每环都写：
user?.address?.street?.name
```

### 3. 两个警告
- **不要过度使用**：只在"确实允许不存在"的地方用。如果 `user` 按逻辑必须存在，就写 `user.address?.street`，让该报的错报出来，否则 bug 被吞掉、更难调试。
- **前面的变量必须已声明**：`user?.address` 中 `user` 从未声明过，照样 `ReferenceError`。

### 4. 短路效应
`?.` 左边不存在时，右边的函数调用/运算**全部不执行**：

```js
let user = null;
let x = 0;
user?.sayHi(x++); // sayHi 没调用，x++ 没执行
x; // 0
```

### 5. 三种形式 + 一个限制
```js
obj?.prop        // obj 存在则取 obj.prop，否则 undefined
obj?.[prop]      // 方括号版本，键是变量时用
obj.method?.()   // 方法存在才调用（method 可能不存在）

delete user?.name; // 与 delete 配合也安全
```
- **不能用于写入**：`user?.name = "John"` 是语法错误（`?.` 只能读和删）。

## 与 Java 对比
| Java | JS | 说明 |
|---|---|---|
| 访问链中间为 `null` → NPE | → TypeError | 同样的痛 |
| `Optional.map(...).map(...).orElse(null)` | `a?.b?.c` | 一行顶 Java 一串 Optional |
| 无对应语法（Groovy/Kotlin 的 `?.` 才有） | `?.` 是 ES2020 语法 | 会 Kotlin/Groovy 的话直接迁移 |
| — | `method?.()`、`obj?.[key]` | 方法调用和动态键也有可选版本 |

**实践建议**：
- 配合 `??` 给默认值：`user?.address?.street ?? "未知地址"`。
- 记住它只对 `null/undefined` 短路，对 `0`、`""` 不短路——这正是它和 `&&` 链的区别。

## 一句话总结
`?.` 在左侧值为 `null/undefined` 时短路返回 `undefined`，三种形式 `?.`、`?.[]`、`?.()` 覆盖属性、动态键、方法调用；只对它前面的那一环生效，不能用于赋值，也不要在"本不应为空"的地方滥用。
