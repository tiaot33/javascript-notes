# 03 垃圾回收

> 原文：`zh.javascript.info/1-js/04-object-basics/03-garbage-collection/article.md`

## 知识点

### 1. 核心概念：可达性（Reachability）
- JS 内存管理自动完成，判断"该不该回收"的标准是**可达性**。
- **根（roots）**：固有的可达值集合，不会被释放：
  - 当前执行函数的局部变量和参数
  - 当前嵌套调用链上其他函数的变量和参数
  - 全局变量
- 从根出发，通过引用或引用链能访问到的值都是**可达的**，保留在内存中；否则被回收。

### 2. 引用被覆盖即可能被回收
```js
let user = { name: "John" };
user = null; // John 不可达 → 被回收
```
但只要有**任意一个**引用还在，对象就存活：
```js
let admin = user;
user = null; // 对象仍可通过 admin 访问，不会被回收
```

### 3. 只有"传入的引用"才算数
- 对象 A 引用对象 B，**不能保证** B 存活；关键是 B 能否从根到达。
- 删除 `family.father` 和 `family.mother.husband` 两个引用后，John 没有传入引用了 → 被回收。

### 4. 无法到达的岛屿
- 一组对象**互相引用但整体与根断开**，整组都会被回收：

```js
family = null;
// John 和 Ann 仍然互相引用（husband/wife），
// 但没有任何根能到达它们 → 整座"孤岛"被回收
```
- **"被引用" ≠ "可达"**，这是与朴素引用计数最大的区别（环形引用也能正确回收）。

### 5. 内部算法：mark-and-sweep（标记-清除）
定期执行：
1. 标记所有根。
2. 沿引用继续标记，标记到的对象不再重复遍历。
3. 直到所有可达引用都访问完。
4. **未被标记的对象全部删除。**

引擎优化（了解即可）：
- **分代收集**：对象分"新"/"旧"，新对象死得快、查得勤；活得久的对象降级为"旧"，检查频率降低。
- **增量收集**：对象集拆成多小块分批清理，用多次小停顿代替一次大停顿。
- **闲时收集**：尽量在 CPU 空闲时运行，减少对代码执行的影响。

### 6. 不能手动控制
- 垃圾回收自动进行，**无法强制执行也无法阻止**。

## 与 Java 对比
| Java（JVM） | JS（V8 等引擎） | 说明 |
|---|---|---|
| GC Roots（栈帧局部变量、静态变量等） | roots（当前函数局部变量、调用链、全局变量） | 概念完全对应 |
| 可达性分析（Reachability Analysis） | 可达性（Reachability） | 同一套理论 |
| 循环引用可被回收（非引用计数） | "无法到达的岛屿"同样被回收 | 都不是引用计数 |
| Mark-Sweep / Mark-Compact | mark-and-sweep | 基本算法相同 |
| 分代：新生代/老年代 | 分代收集：新对象/旧对象 | 思路一致 |
| `System.gc()` 只是"建议"，不保证执行 | 连建议的 API 都没有，完全自动 | JS 对 GC 的控制权更小 |

**对 Java 开发者**：这一章几乎没有新知识，把 JVM 的可达性分析、分代思想平移过来即可。唯一要记住的是 JS 层面**没有任何触发或干预 GC 的手段**。

## 一句话总结
JS 用"可达性"判断对象生死：从根（当前函数、调用链、全局变量）出发能到达的对象存活，否则被 mark-and-sweep 回收；互相引用但整体与根断开的"孤岛"也会整体回收；GC 全自动且不可干预。
