# 09 对象 —— 原始值转换

> 原文：`zh.javascript.info/1-js/04-object-basics/09-object-toprimitive/article.md`

## 知识点

### 0. 背景：JS 不支持运算符重载
- `obj1 + obj2`、`alert(obj)` 时，对象会被**自动转换为原始值**再运算，结果也是原始值。
- 因此 `obj1 + obj2` 的结果**不可能**是对象——无法实现"向量相加"这类设计。实际项目中对对象做数学运算，基本都是 bug。
- 例外场景：`Date` 对象相减（`date1 - date2` 得到毫秒差）。

### 1. 三种转换规则
- **没有对象→布尔的转换**：所有对象在布尔上下文都是 `true`（哪怕空对象 `{}`）。
- 数字转换：数学运算（减、一元加 `+obj`、`Number(obj)`、大小比较）。
- 字符串转换：`alert(obj)` 之类的输出、把对象当属性键。

### 2. hint：引擎如何决定转成什么
| hint | 触发场景 |
|---|---|
| `"string"` | `alert(obj)`、`anotherObj[obj] = 123`（作键） |
| `"number"` | `Number(obj)`、一元 `+obj`、`date1 - date2`、`user1 > user2` |
| `"default"` | 运算符"不确定"时：二元 `+`、`obj == 原始值` |

- 注意：`<` `>` 既可用于字符串也可用于数字，但用 `"number"` hint（历史原因）。
- 除 `Date` 外，所有内建对象的 `"default"` 都按 `"number"` 处理；自己实现时照做即可。

### 3. 转换算法（依次尝试）
1. 若存在 `obj[Symbol.toPrimitive](hint)` → 调用它，处理**所有** hint。
2. 否则 hint 为 `"string"` → 先试 `obj.toString()`，没有再试 `obj.valueOf()`。
3. 否则（`"number"` / `"default"`）→ 先试 `obj.valueOf()`，没有再试 `obj.toString()`。

### 4. `Symbol.toPrimitive`：一个方法接管所有转换
```js
let user = {
  name: "John",
  money: 1000,

  [Symbol.toPrimitive](hint) {
    // hint 是 "string" | "number" | "default"
    return hint == "string" ? `{name: "${this.name}"}` : this.money;
  }
};

alert(user);     // hint: string  -> {name: "John"}
alert(+user);    // hint: number  -> 1000
alert(user + 500); // hint: default -> 1500
```

### 5. 老派做法：`toString` / `valueOf`
- 普通对象默认自带：
  - `toString()` → `"[object Object]"`
  - `valueOf()` → 返回对象自身（因此被忽略，可当它不存在）

```js
let user = {
  name: "John",
  money: 1000,
  toString() { return `{name: "${this.name}"}`; },  // 管 hint="string"
  valueOf()  { return this.money; }                 // 管 hint="number"/"default"
};
```
- 偷懒技巧：只实现 `toString()`，它会在所有转换中被调用（`valueOf` 默认返回对象被忽略）：

```js
let user = { name: "John", toString() { return this.name; } };
alert(user);      // John
alert(user + 500); // John500（二元 + 把 500 拼成字符串）
```

### 6. 返回值规则
- 这些方法**必须返回原始值**，但**不强制返回 hint 对应的类型**（hint 是 "number" 也可以返回字符串）。
- `toString`/`valueOf` 返回对象 → 结果被**静默忽略**（历史原因，不报错）。
- `Symbol.toPrimitive` 更严格：**必须返回原始值，否则报错**。

### 7. 进一步的二次转换
运算分两个阶段：先对象→原始值，再按运算符需要继续转：

```js
let obj = { toString() { return "2"; } };
alert(obj * 2); // 4：先转字符串 "2"，乘法再把 "2" 转成数字 2
alert(obj + 2); // "22"：先转字符串 "2"，二元 + 偏好字符串 → 拼接
```

## 与 Java 对比
| Java | JS | 说明 |
|---|---|---|
| 不支持运算符重载 | 同样不支持 | 但 JS 会**自动转原始值再算**，不报错，容易掩盖 bug |
| `toString()` 用于打印/日志 | `toString()` 还参与隐式转换 | `alert(obj)` ≈ `System.out.println(obj)` 自动调 `toString()` |
| 无 `valueOf` 对应物（`Integer.valueOf` 是静态工厂，别混淆） | `valueOf()` 对象→原始值（数字优先） | 数学运算时优先于 `toString` 被调用 |
| 无 hint 概念 | `"string"/"number"/"default"` 三种 hint | 自定义转换时可区分场景 |
| 模板方法/接口（如 `Comparable`） | `Symbol.toPrimitive` 一个钩子管所有转换 | 更接近"运算符重载"的体验 |

**实践建议**：
- 自定义对象一般只实现 `toString()`，返回人类可读表示，方便日志和调试。
- 生产代码里避免依赖隐式转换做运算（如 `user + 500`），可读性差，显式调用方法更清楚。

## 一句话总结
对象参与运算/输出时按 hint（string/number/default）自动转原始值：优先 `Symbol.toPrimitive(hint)`，否则 string 走 `toString→valueOf`、number/default 走 `valueOf→toString`；方法必须返回原始值；实践中实现好 `toString()` 即可。
