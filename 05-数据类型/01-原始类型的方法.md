# 01 原始类型的方法

> 原文：`zh.javascript.info/1-js/05-data-types/01-primitives-methods/article.md`

## 知识点

### 1. 悖论：原始类型不是对象，却能调用方法
- 7 种原始类型：`string`、`number`、`bigint`、`boolean`、`symbol`、`null`、`undefined`。
- 对象能存多个值、能挂方法，但比原始类型"更重"（额外资源开销）。
- JS 的解决方案：**原始类型保持轻量，但允许像对象一样访问方法**。

### 2. 对象包装器（核心机制）
调用原始类型的方法时，引擎在幕后做三件事：

```js
let str = "Hello";
alert( str.toUpperCase() ); // HELLO
```

1. 访问 `str` 的属性时，**临时创建**一个包含该字符串值的特殊"对象包装器"，它带有 `toUpperCase` 等方法。
2. 方法执行，返回新字符串。
3. 包装器对象**立即销毁**，只留下原始值。

- 每种原始类型对应不同的包装器：`String`、`Number`、`Boolean`、`Symbol`、`BigInt`。
- 引擎高度优化了这个过程，甚至可能跳过创建对象，但行为上"表现得好像创建了"。
- 所以：**原始类型有方法，但依然轻量**。

### 3. 陷阱：不要用 `new String/Number/Boolean`
像 Java 一样显式 new 包装器在 JS 中语法上可行，但**极不推荐**：

```js
alert( typeof 0 );            // "number"
alert( typeof new Number(0) ); // "object"!

let zero = new Number(0);
if (zero) { /* 永远执行！对象是 truthy，哪怕包的是 0 */ }
```

- 但**不带 `new`** 调用 `String/Number/Boolean` 是安全且常用的——它们是类型转换函数：

```js
let num = Number("123"); // 字符串 → 数字（原始类型）
```

### 4. `null` 和 `undefined` 没有任何方法
- 这两个"最原始"的值**没有对应的包装器**。
- 访问它们的属性直接报错（这是 JS 最常见的运行时错误之一）：

```js
alert(null.test); // TypeError
```

## 与 Java 对比
| Java | JS | 说明 |
|---|---|---|
| `int`/`Integer` 自动装箱拆箱 | 原始值调用方法时临时包装 | 概念相似，但 JS 的包装对象用完即毁，对开发者不可见 |
| `new Integer(0)` 已废弃（Java 9+） | `new Number(0)` 语法可行但极不推荐 | JS 中包装对象 typeof 是 `"object"`，且恒为 truthy，坑更深 |
| `Integer.valueOf("123")` | `Number("123")` | 不带 `new` 的调用 = 类型转换，返回原始值 |
| `null` 调方法抛 NPE | `null`/`undefined` 访问属性抛 TypeError | 都是高频事故源头 |

## 一句话总结
原始类型通过"用完即毁的临时包装器"获得方法调用能力，既轻量又方便；千万别用 `new Number()` 之类的构造器（会得到恒为 truthy 的对象）；`null`/`undefined` 没有任何方法，碰属性就报错。
