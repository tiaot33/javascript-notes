# 02 F.prototype

> 原文：`zh.javascript.info/1-js/08-prototypes/02-function-prototype/article.md`
> 上一篇讲"对象怎么继承对象"，这一篇讲"`new F()` 造出来的对象，它的原型从哪来"。答案是构造函数上一个**叫 `prototype` 的普通属性**。这是 ES6 `class` 出现之前 JS 实现"类"的唯一正规方式，也是你几年前学 JS 时看到的那套写法。

## 知识点

### 1. `F.prototype` 是什么
- `F.prototype` 是函数 `F` 上一个**名字恰好叫 "prototype" 的常规属性**，不是 `[[Prototype]]`。
- 它的唯一特殊作用：**执行 `new F()` 时，把新对象的 `[[Prototype]]` 设为 `F.prototype` 的值**。（`new` 的三步流程见 04-对象基础知识/06，这一步发生在"创建空对象"时。）

```js
let animal = { eats: true };

function Rabbit(name) {
  this.name = name;
}
Rabbit.prototype = animal; // "new Rabbit 造出的对象，[[Prototype]] 都指向 animal"

let rabbit = new Rabbit("White Rabbit"); // rabbit.__proto__ === animal
rabbit.eats; // true
```

三者关系（务必分清）：
```
Rabbit（构造函数） ──.prototype（普通属性，横向）──▶ animal
                                                       ▲
rabbit（实例）    ──[[Prototype]]（继承关系，纵向）──────┘
```
- `F.prototype` 的值必须是**对象或 `null`**，其他值不起作用。
- 只有**函数上的** `prototype` 且**通过 `new` 调用**时才有这个特殊含义。普通对象上叫 `prototype` 的属性只是个普通属性，毫无特殊性：

```js
let user = { name: "John", prototype: "Bla-bla" }; // 这里只是普通属性
```

### 2. `F.prototype` 只在 `new` 那一刻起作用
- `new F()` 时读一次 `F.prototype`，把引用塞给新对象的 `[[Prototype]]`，之后两者再无绑定。
- 后来 `F.prototype = 另一个对象`，**只影响之后 new 出来的对象**，已存在的对象仍指向旧原型。

练习题"修改 prototype"四种情况（前提：`Rabbit.prototype = { eats: true }; let rabbit = new Rabbit();`）：

| 之后执行 | `rabbit.eats` | 原因 |
|---|---|---|
| `Rabbit.prototype = {}` | `true` | 整体替换只影响新对象，`rabbit` 仍指向旧原型对象 |
| `Rabbit.prototype.eats = false` | `false` | 原型对象本身被修改，`rabbit` 引用的就是它，改动可见 |
| `delete rabbit.eats` | `true` | `delete` 只作用于对象自身，`rabbit` 自己没有 `eats`，无事发生 |
| `delete Rabbit.prototype.eats` | `undefined` | 原型上的属性被删了，链上再无 `eats` |

一句话：**替换引用 vs 修改对象内容**，和 Java 里"给变量重新赋值"与"修改变量所指对象"的区别完全一样。

### 3. 默认的 `F.prototype` 与 `constructor` 属性
- **每个函数**（箭头函数没有）天生就有 `prototype` 属性，默认值是 `{ constructor: F }`——一个只有 `constructor` 属性、指回函数自身的对象。

```js
function Rabbit() {}
// 默认：Rabbit.prototype = { constructor: Rabbit }
Rabbit.prototype.constructor === Rabbit; // true

let rabbit = new Rabbit();
rabbit.constructor === Rabbit; // true，通过 [[Prototype]] 继承得到
```

- 用途：手里有个对象但不知道它的构造函数（比如来自第三方库），可以用 `obj.constructor` 造一个同类对象：

```js
let rabbit2 = new rabbit.constructor("Black Rabbit");
```

### 4. 坑：JS 不保证 `constructor` 正确
- `constructor` 只是默认 `prototype` 对象上的一个普通属性，**引擎不会维护它**，之后发生什么完全取决于我们。
- 整体覆盖 `F.prototype = { ... }` 后，默认对象没了，`constructor` 也跟着丢了：

```js
function Rabbit() {}
Rabbit.prototype = { jumps: true };

let rabbit = new Rabbit();
rabbit.constructor === Rabbit; // false！
```
- 此时 `rabbit.constructor` 沿链一路找到 `Object.prototype.constructor`，也就是 `Object`。练习题里 `new user.constructor('Pete')` 因此变成了 `new Object('Pete')`，`user2.name` 是 `undefined`，而且**不报错**，非常隐蔽。

两种正确做法：

```js
// 做法 1（推荐）：不整体覆盖，往默认 prototype 上追加
Rabbit.prototype.jumps = true; // constructor 保留

// 做法 2：整体覆盖时手动补回 constructor
Rabbit.prototype = {
  jumps: true,
  constructor: Rabbit
};
```

## 与 Java 对比
| Java | JS | 说明 |
|---|---|---|
| `class Rabbit { ... }` 定义类，方法放在类里 | `function Rabbit() {}` + `Rabbit.prototype.method = ...` | ES5 时代的"类"：构造函数管初始化，`prototype` 对象管共享方法。ES6 `class` 就是这套的语法糖 |
| 类的方法表由 JVM 维护，运行时不可改 | `F.prototype` 是普通对象，随时可增删方法，新旧实例都能看到 | 动态性的来源，也是 monkey patch 的来源 |
| `obj.getClass()` 永远准确，JVM 保证 | `obj.constructor` 只是个可丢失、可篡改的普通属性 | 不要拿它做可靠的类型判断；`instanceof` 也不依赖它（后续章节讲） |
| `obj.getClass().getConstructor().newInstance()` 反射造同类对象 | `new obj.constructor()` | 前提是没人破坏 `constructor` |
| 无对应概念 | `F.prototype`（属性）≠ `obj.[[Prototype]]`（内部槽位） | JS 初学者最大的命名混淆点，见上面的三者关系图 |

## 一句话总结
`F.prototype` 是构造函数上一个名叫 `prototype` 的**普通属性**，唯一特殊之处是 `new F()` 时被赋给新对象的 `[[Prototype]]`（只在 new 那一刻生效，之后替换 `F.prototype` 不影响已有实例，但修改该对象的内容会立刻被所有实例看到）；每个函数默认 `F.prototype = { constructor: F }`，实例因此能通过 `obj.constructor` 找回构造函数，但引擎**不保证** `constructor` 正确，整体覆盖 `prototype` 会丢掉它，所以应当往默认 `prototype` 上追加属性，或覆盖时手动写回 `constructor: F`。
