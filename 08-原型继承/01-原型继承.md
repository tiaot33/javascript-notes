# 01 原型继承

> 原文：`zh.javascript.info/1-js/08-prototypes/01-prototype-inheritance/article.md`
> JS 继承的**底层机制**。Java 靠 class 继承，JS 靠对象之间的"原型链"委托查找；ES6 的 `class` 只是这套机制的语法糖，所以这一章必须先吃透。

## 知识点

### 1. `[[Prototype]]`：每个对象都有的隐藏引用
- 每个对象都有一个内部隐藏属性 `[[Prototype]]`，值要么是 `null`，要么是**对另一个对象的引用**，被引用的对象称为"原型"。
- 读取 `obj.prop` 时，如果 `obj` 自身没有这个属性，JS 会**自动沿着 `[[Prototype]]` 向上查找**，找到为止（整条链都没有则返回 `undefined`）。这就是"原型继承"。
- 方法也一样：`rabbit.walk()` 在 `rabbit` 上没找到就去原型里找。

```js
let animal = {
  eats: true,
  walk() { alert("Animal walk"); }
};
let rabbit = {
  jumps: true,
  __proto__: animal   // 设置 rabbit.[[Prototype]] = animal
};

rabbit.eats;   // true  （来自 animal）
rabbit.walk(); // Animal walk（来自 animal）
rabbit.jumps;  // true  （自己的）
```

### 2. `__proto__` 与 `[[Prototype]]` 不是一回事
- `[[Prototype]]` 是规范里的**内部槽位**，代码里无法直接写出来。
- `__proto__` 是它的历史遗留 **getter/setter**（访问器属性），`rabbit.__proto__ = animal` 本质是调 setter 去改 `[[Prototype]]`。
- 现代写法是 `Object.getPrototypeOf / Object.setPrototypeOf`（第 4 篇讲），但 `__proto__` 所有环境都支持，教程为直观继续用它；在对象字面量里写 `__proto__: xxx` 是被规范认可的用法。

### 3. 原型链（chain）与两条限制
```js
let longEar = { earLength: 10, __proto__: rabbit }; // longEar → rabbit → animal
longEar.walk(); // 一路向上找到 animal.walk
```
- 查找顺序：自身 → 原型 → 原型的原型 → … → `null` 终止。
- 限制 1：**不能成环**，赋值导致循环引用会直接抛错。
- 限制 2：`__proto__` 只接受**对象或 `null`**，其他类型（字符串、数字…）的赋值被**静默忽略**（第 4 篇的 `__proto__` 字典 bug 正源于此）。
- **只有一个 `[[Prototype]]`**：一个对象不能同时继承两个对象（单继承）。

### 4. 写入/删除不走原型
- 原型**只用于读取**。`obj.prop = value` 和 `delete obj.prop` 都**直接作用在 `obj` 自身**，不会碰原型。
- 给 `rabbit.walk` 赋新函数后，`rabbit` 就有了自己的 `walk`，原型上的被"遮蔽"（shadow），类似 Java 的方法重写，但这里是运行时逐个对象地遮蔽。

```js
rabbit.walk = function() { alert("Rabbit! Bounce-bounce!"); };
rabbit.walk(); // 自己的，不再去原型找
```

- **例外：访问器属性（setter）**。赋值 `admin.fullName = "Alice Cooper"` 时，如果 `fullName` 在原型上是 setter，那赋值实际上是**调用 setter 函数**，所以会触发原型上的 setter。但 setter 里的 `this` 是 `admin`，最终写入的还是 `admin` 自己的 `name/surname`，原型 `user` 不受影响。

### 5. `this` 不受原型影响（核心！）
- **方法在哪找到无所谓，调用时 `this` 永远是点号前面的对象。**
- `rabbit.sleep()` 里 `this.isSleeping = true` 写在 `rabbit` 上，`animal` 不受影响。
- 结论：**方法是共享的，状态不是**。一个"大对象"放方法，多个子对象继承它并各自维护自己的状态。
- 属性查找和执行是两回事：先沿链找到 `rabbit.eat`，然后以 `this = rabbit` 执行。

```js
let animal = {
  walk() { if (!this.isSleeping) alert(`I walk`); },
  sleep() { this.isSleeping = true; }
};
let rabbit = { name: "White Rabbit", __proto__: animal };

rabbit.sleep();
rabbit.isSleeping; // true
animal.isSleeping; // undefined
```

### 6. 坑：原型上的可变对象会被所有继承者共享
练习题"两只仓鼠"：`hamster.stomach = []` 放在原型上，执行 `this.stomach.push(food)` 时——
1. `this = speedy`，在 `speedy` 上找不到 `stomach`；
2. 沿原型链在 `hamster` 上找到那个数组；
3. `push` 修改的是**原型上的同一个数组** → 所有仓鼠共用一个胃。

```js
let hamster = {
  stomach: [],
  eat(food) { this.stomach.push(food); } // 读 → 走原型 → 改到共享数组
};
let speedy = { __proto__: hamster };
let lazy   = { __proto__: hamster };
speedy.eat("apple");
lazy.stomach; // ["apple"]  ❌
```
- 区别：`this.stomach = [food]` 是**赋值**，直接写到 `speedy` 自己身上，不会有这个问题；`this.stomach.push()` 是**先读后改**，读走了原型。
- 规矩：**描述某个对象自身状态的属性，都应该写在该对象自身上**（如在 `speedy`、`lazy` 里各自声明 `stomach: []`），原型只放方法。对 Java 开发者：这等价于"不要把实例状态放在 `static` 字段里"。

### 7. `for..in` 会遍历继承属性，其他方法不会
```js
let animal = { eats: true };
let rabbit = { jumps: true, __proto__: animal };

Object.keys(rabbit);            // ["jumps"]        只有自己的
for (let prop in rabbit) ...;   // jumps, eats      自己的 + 继承的（可枚举）
```
- 过滤继承属性用 `obj.hasOwnProperty(key)`：只对自身（非继承）属性返回 `true`。
- `hasOwnProperty` 本身来自 `Object.prototype`（字面量对象默认的原型），但它没出现在 `for..in` 里，因为它是 `enumerable: false`。`for..in` 只列**可枚举**属性，`Object.prototype` 上的内建方法全是不可枚举的。
- 几乎所有其他键/值方法（`Object.keys/values/entries`）都**只看自身属性**，忽略继承的。

完整链：`rabbit → animal → Object.prototype → null`。

### 8. 练习题要点
- **删除后的回退**：`rabbit` 自己有 `jumps: true`，`delete rabbit.jumps` 后读到的是原型 `animal.jumps`（`null`），再 `delete animal.jumps` 后才是 `undefined`。删除只删自己的，删完"露出"原型上的值。
- **性能**：现代引擎会缓存属性查找位置（inline cache），从原型链深处取属性与从自身取**没有可感知的性能差异**，且原型链改动时缓存自动失效，无需为此把属性拍平到对象上。

## 与 Java 对比
| Java | JS | 说明 |
|---|---|---|
| 类继承：`class Rabbit extends Animal`，编译期确定 | 对象继承：`rabbit.__proto__ = animal`，运行时可改 | JS 没有"类是模板、对象是实例"的硬性区分，对象直接继承对象（委托查找，不是拷贝） |
| 方法查找：按类层次向上找虚方法 | 属性查找：按原型链向上找 | 思路相同，但 JS 对**所有属性**（含数据）都这么找，且找不到返回 `undefined` 而非编译错误 |
| 继承方法中的 `this` 是实际对象 | 同样，`this` 是点号前的对象 | 这点两者一致，Java 开发者不用重新理解 |
| 子类字段覆盖父类字段（field hiding） | 对象自身属性遮蔽原型属性 | JS 是运行时逐对象遮蔽，`delete` 后又能"露出"原型的值 |
| `static` 可变字段被所有实例共享，是经典 bug 源 | 原型上的可变对象（数组/对象）被所有继承者共享 | 完全对应的坑：状态放实例上，原型/类只放方法 |
| 单继承 + 多接口 | 只有一个 `[[Prototype]]`，单继承 | 多重复用靠方法借用/mixin（后续章节） |
| 反射 `getDeclaredFields` 只拿本类 vs `getFields` 含继承 | `Object.keys` 只拿自身 vs `for..in` 含继承 | `hasOwnProperty` 用来区分 |

## 一句话总结
每个对象都有隐藏的 `[[Prototype]]`（用 `__proto__` 读写，只能是对象或 `null`，不能成环，只能有一个），**读取**缺失属性时沿原型链向上查找，**写入/删除只作用于对象自身**（setter 除外）；无论方法在链上哪里找到，`this` 都是点号前的对象，因此方法共享而状态各自独立，但原型上的可变对象（如数组）会被所有继承者共用，实例状态务必写在实例自身；`for..in` 会遍历继承的可枚举属性，`Object.keys` 等只看自身，区分用 `hasOwnProperty`。
