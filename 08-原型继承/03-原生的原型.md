# 03 原生的原型

> 原文：`zh.javascript.info/1-js/08-prototypes/03-native-prototypes/article.md`
> 前两篇的机制不是给用户代码特供的，**JS 自身的内建对象全靠它**：`[]`、`{}`、函数、甚至字符串的方法，都来自各自的 `prototype`。理解这一层，就明白为什么 `{}` 是"空"的却能调 `toString`，以及为什么"给 String 加方法"在 JS 里是可能的。

## 知识点

### 1. `Object.prototype`：一切的顶端
- `let obj = {}` 等价于 `new Object()`，`Object` 是内建构造函数，所以 `obj.[[Prototype]] === Object.prototype`。
- `Object.prototype` 是个大对象，挂着 `toString`、`hasOwnProperty`、`valueOf` 等方法，`obj.toString()` 就是从它那里取到的，所以空对象也能输出 `"[object Object]"`。
- `Object.prototype` 再往上就是 `null`，它是所有原型链的终点。

```js
let obj = {};
obj.__proto__ === Object.prototype;             // true
obj.toString === Object.prototype.toString;     // true
Object.prototype.__proto__;                     // null
```

### 2. 其他内建原型：`Array` / `Function` / `Date` …
- `[1, 2, 3]` 内部等价于 `new Array()`，所以数组的 `[[Prototype]]` 是 `Array.prototype`，数组方法（`push`、`map`、`join`…）全在那上面。
- 按规范，**所有内建原型的顶端都是 `Object.prototype`**，这就是"一切都继承自对象"的含义。

```js
let arr = [1, 2, 3];
arr.__proto__ === Array.prototype;                    // true
arr.__proto__.__proto__ === Object.prototype;         // true
arr.__proto__.__proto__.__proto__;                    // null

function f() {}
f.__proto__ == Function.prototype;                    // true，call/apply/bind 都在这
f.__proto__.__proto__ == Object.prototype;            // true
```

- 这种设计**省内存**：方法只在 prototype 上存一份，对象本身只存数据（数组元素、对象属性、日期值）。
- **就近覆盖**：`Array.prototype` 和 `Object.prototype` 都有 `toString`，链上更近的 `Array.prototype.toString` 胜出，所以 `alert([1,2,3])` 输出 `1,2,3` 而不是 `[object Object]`。函数也有自己的 `toString`（输出源码）。
- Chrome 控制台用 `console.dir(arr)` 可以展开看到 `[[Prototype]]` 层级。

原型链全景：
```
[1,2,3] → Array.prototype    → Object.prototype → null
f()     → Function.prototype → Object.prototype → null
{}      → Object.prototype   → null
```

### 3. 原始类型的方法从哪来
- 字符串、数字、布尔值**不是对象**，但访问 `"abc".toUpperCase()` 时，引擎临时创建包装对象（`new String(...)` 等），调完方法即销毁（规范如此描述，引擎会优化掉）。
- 这些方法就放在 `String.prototype`、`Number.prototype`、`Boolean.prototype` 上。
- **`null` 和 `undefined` 没有包装对象**，没有原型，没有任何属性和方法——访问 `null.xxx` 直接 `TypeError`。

（回顾 05-数据类型/01-原始类型的方法。）

### 4. 修改原生原型：能做，但基本别做
```js
String.prototype.show = function() { alert(this); };
"BOOM!".show(); // 对所有字符串生效
```
- 原生原型是**全局共享**的，两个库都加 `String.prototype.show` 就会互相覆盖，冲突几乎无法排查。
- **现代编程里唯一被接受的场景：polyfill**——规范已经定义、但当前引擎还没实现的方法，先检测再手动补上：

```js
if (!String.prototype.repeat) {   // 先检测，没有才补
  String.prototype.repeat = function(n) {
    return new Array(n + 1).join(this);   // 不完美的实现通常也够用
  };
}
"La".repeat(3); // LaLaLa
```

- 练习题示范了"给所有函数加方法"：往 `Function.prototype` 上加，方法里的 `this` 就是被调用的那个函数。

```js
// 简单版：ms 毫秒后执行函数
Function.prototype.defer = function(ms) {
  setTimeout(this, ms);
};
f.defer(1000);

// 装饰器版：返回延迟执行的包装器，透传参数和 this
Function.prototype.defer = function(ms) {
  let f = this;
  return function(...args) {
    setTimeout(() => f.apply(this, args), ms);
  };
};
f.defer(1000)(1, 2);                 // 1 秒后 alert 3
user.sayHi = user.sayHi.defer(1000); // 用 apply 透传 this，对象方法也能用
```

### 5. 从原型中借用方法
- 方法借用（06-函数进阶内容/09 讲过）：把一个对象的方法复制到另一个对象上用。
- 很多内建方法（如 `Array.prototype.join`）的算法**只依赖索引和 `length`**，不检查调用者是不是真数组，所以类数组对象可以直接借：

```js
let obj = { 0: "Hello", 1: "world!", length: 2 };
obj.join = Array.prototype.join;
obj.join(','); // Hello,world!
```
- 另一种方式：`obj.__proto__ = Array.prototype`，一次性拿到全部数组方法。但对象只能有一个原型，如果 `obj` 已经继承了别的对象，这条路就走不通了。
- 借用比继承灵活：可以按需从多个对象各借几个方法，绕过单继承限制。

## 与 Java 对比
| Java | JS | 说明 |
|---|---|---|
| `java.lang.Object` 是所有类的根 | `Object.prototype` 是所有原型链的根，再往上是 `null` | `toString/hashCode/equals` ↔ `toString/valueOf/hasOwnProperty` |
| 方法在类的方法区存一份，实例只存字段 | 方法在 `X.prototype` 存一份，对象只存数据 | 内存模型思路一致 |
| 子类重写 `toString` 覆盖父类实现 | `Array.prototype.toString` 遮蔽 `Object.prototype.toString` | 就近原则相同 |
| `int` 自动装箱成 `Integer` 才能调方法 | 原始值临时包装成 `String/Number/Boolean` 对象 | 都是"自动装箱"，JS 的包装对象用完即弃 |
| `String` 是 `final` 类，无法给它加方法；Kotlin 扩展函数是编译期静态分派 | `String.prototype.xxx = ...` 运行时给**所有**字符串加方法 | JS 可以 monkey patch，但除 polyfill 外都不建议 |
| 新 API 需要升级 JDK，没有 polyfill 概念 | polyfill：检测缺失后手动往原生原型上补规范方法 | 前端兼容老浏览器的常规手段，多由 core-js 等库统一提供 |
| 接口契约：必须 `implements List` 才能当 List 用 | 鸭子类型：有索引和 `length` 就能借 `Array.prototype.join` | 借用方法是 JS 的多重复用手段之一 |

## 一句话总结
所有内建对象都遵循"方法放 prototype、对象只存数据"的模式：`{}` → `Object.prototype` → `null`，`[]` → `Array.prototype` → `Object.prototype`，函数 → `Function.prototype` → `Object.prototype`，链上就近的方法胜出（所以数组的 `toString` 输出 `1,2,3`）；原始值靠临时包装对象取 `String/Number/Boolean.prototype` 上的方法，`null/undefined` 没有包装器；原生原型可以修改但全局共享、容易冲突，**只有 polyfill（补规范里有而引擎没有的方法）才被接受**；类数组对象可以借用 `Array.prototype` 的方法（如 `join`），因为它们只依赖索引和 `length`。
